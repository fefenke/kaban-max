# Изменения

## 0.2.3 — 2026-11-24

- Hotfix обновлений: raw fallback для manifests/установщика при отказе GitHub API; пакеты и SHA256SUMS через публичные release URLs. Zapret2 использует проверенный резервный snapshot с прежней проверкой SHA256.

- Core r40: устойчивость WARP с подтверждёнными UDP-портами, ограниченным восстановлением и редким сохранением подсказки порта.
- Авторутинг: применённый IP охватывает все устройства/порты выбранной секции; успешные Pending results не протухают. Исходная ошибка, новые ошибки и наблюдённые домены Applied сохраняются отдельно в bounded RAM через restart службы. Понятные timeout сообщения, без пустой ошибки.
- Ограниченные журналы и мониторинг, IPv6 FakeIP и уровни сетевых логов; исправления ownership/scope при работе с реестром.
- Очищены текущие файлы и метаданные изображений; добавлены source/package privacy gates и полный GPL core source. [Проверки, native install и границы](docs/RELEASE_023.md).

## 0.2.9 / r39 — установленный preview, не опубликовано · 2026-11-24

- Применённый web IP охватывает все устройства/порты выбранной секции. Старые approvals мигрируют без повторного применения; соседние секции/IP и явные исключения защищены. Удалён uncovered status, исправлено скрытие Pending другого устройства. [Проверки и установка](docs/PREVIEW_029.md).

- Per-profile durable WARP local UDP port hints: ten healthy minutes, at most one changed hint commit per router boot; unchanged hints never write flash. See [contract and verification](docs/WARP_PORT_HINTS.md).

## 0.2.7 — локальная приёмка, не опубликовано · 2026-11-24

- Удалена настройка часового хранения ошибок: неразобранные записи и успешные результаты хранятся до разбора под общим бюджетом памяти, без протухания и автоматических повторов. Суточная запись изменённых правил во flash не менялась.
- Установлен core r37: оба WARP и fallback прошли пять реальных перезапусков KabanMax подряд. Собственные установочные файлы убраны, flash занято около 33 МиБ. [Точные проверки и ограничения](docs/PREVIEW_027.md).

## 0.2.6 — локальная приёмка, не опубликовано · 2026-11-24

- Авторутинг: успешная проверка сохраняется до удаления/применения/исключения записи; не протухает, не повторяется автоматически и переносится через restart вместе с временем и результатами проб. Новые ошибки исходного маршрута не стирают успех альтернативы. Кнопка перепроверки не добавляется.
- WARP: standby начинает handshake при запуске, если keepalive явно не задан. До первого успешного handshake допускаются максимум три быстрых смены неотвечающего UDP-потока, затем прежний 90s backoff. Здоровые сессии и pinned port сохраняют прежнюю политику. [Проверки и установка](docs/PREVIEW_026.md).
- Core r37 сохраняет подтверждённый локальный UDP-порт как мягкую подсказку для следующего старта, вместо обязательного отказа от известного рабочего пути. Занятый порт не мешает старту; пользовательский listen_port не заменяется.

## 0.2.5 — локальная приёмка, не опубликовано · 2026-11-24

Просроченный результат не разрешает применение маршрута. [Проверки](docs/PREVIEW_025.md).

Прямые проверки не используют VPN/локальный DNS, сохраняют TLS-проверку и ограничены по времени/памяти; причину ISP не выдумывают.

- IPv6 FakeIP перенесён из ULA в `2001:2::/112` для Chromium/Edge PNA/LNA, без увеличения пула; согласованы nft, guards, диагностика и миграция сохранённых записей. [Контракт и проверки](docs/NETWORK_AVAILABILITY.md). Не установлено/не опубликовано.

- Core: в Debug перенесены ошибки завершения TCP, routine no-route/not-connected/reset/broken-pipe, отсутствующий FakeIP, malformed DNS, служебный CHAOS/TXT REFUSED и неподтверждённые fallback-пробы. Подтверждённые fallback failures, TLS/auth и ошибки управления сохраняются; дополнительный текущий контракт DNS/WAN/refused/timeout описан выше. Это изменение журналирования, не исправление сети. [Точная политика](docs/LOGGING.md).

- Ограничена память диагностики при Info/Trace: журнал до 256 КиБ/2048 записей, ограниченные строки/чтение/RPC и освобождение снимков. Core r25 формирует до 200 последних соединений без полного массива; LuCI показывает реальное общее число и неполноту списка. Фильтры действуют на показанные строки; отсутствие в снимке не означает закрытие. Ошибки превышения безопасного размера RPC объясняются в UI. [Контракт и локальные проверки](docs/LOGGING.md); на устройства не устанавливалось.

- Инженерная документация: короткий актуальный контекст для новых чатов, один ассистент без агентов, `resource budgeting`, карта компонентов и обязательный doc update. Добавлены source-facts/links/change-coverage проверки, CI и архив прежних документов с SHA256. Runtime-поведение этой реорганизацией не менялось.

- Авторутинг r24: глобальные настройки сохранения (`1d`), срока диагностики (`1h`) и памяти (`4 МиБ`). Компактные маршруты/исключения записываются только при изменении; pressure checkpoint ограничен 15 минутами.
- Вместо 64 записей — byte admission и очистка устаревшей диагностики. Действующие grants/exclusions сохраняются; ограничены также in-flight metadata, нет системного drop_caches/рестартов для очистки.
- Реестры и действия работают за первой сотней записей; bulk остаётся source/filter scoped и выполняется по 8 ID. [Схема, замеры и границы](docs/AUTO_ROUTING_STORAGE.md).

- Авторутинг r23 игнорирует EAGAIN/EWOULDBLOCK, сохраняя реальные сетевые timeout.
- Устранены ложное выключение секции при отзыве уже исчезнувшего маршрута и отзыв сохранённых grants при сбое private checkpoint.
- Исходная секция не отображается как рабочая альтернатива; состояние runtime disabled объясняется в реестре. Ошибки №1/5 не затронуты.
- [Регрессии, проверки и аппаратные ограничения](docs/AUTO_ROUTING_FIELD_ERRORS.md).

## 0.2.2

K.A.B.A.N.-MAX 0.2.2 prerelease, ядро 1.14.4-r22.

- Применённый IP теперь охватывает все порты TCP/UDP в исходной секции и области устройства/входа. Существующие обычные IP-правила при загрузке получают ту же семантику. Условия самой секции, защищённые назначения и ограничения устройств сохраняются.
- Ошибка другого порта выбранного маршрута отображается в той же записи с номером порта. Новая ошибка исходного маршрута после применения не выдаётся за отсутствие ошибок. Если у объединённого IP есть другая неохваченная область устройства/входа, интерфейс сообщает об этом, а не скрывает проблему за здоровым правилом.
- Порт443 больше не означает HTTPS. Для нераспознанного протокола показывается «Работа протокола не подтверждена», автоматическое применение не разрешается, ручной выбор остаётся доступным. WhatsApp Noise verifier в эту версию не добавлен. Проверка одного порта не доказывает работу остальных.
- Загрузчик интерфейса пробует Raw GitHub после отказа основного пути, с таймаутами15 секунд. Команда установки ниже тоже имеет резервный Raw-адрес. Raw используется только для install.sh; пакеты по-прежнему загружаются из релиза с проверкой SHA256.
- HTTP403 без подтверждённого исчерпания квоты больше не называется лимитом60 запросов; HTTP429 и подтверждённая нулевая квота различаются.
- При недостатке RAM установщик временно останавливает работающий KabanMax и повторно проверяет память. При ошибке загрузки/проверки он восстанавливает сервис; отдельный RAM-watchdog делает попытку восстановления после гибели процесса установщика. Это восстановление временной остановки, а не гарантия полного отката любой ошибки пакетного менеджера. Логи и счётчики не пишутся во flash на каждое событие.

Проверки: три новые core-регрессии, семь пакетов с race detector из pinned upstream+patches0001–0022,96 backend-файлов,176 frontend-файлов/1694 теста,TypeScript/build/lint и1166/1166 переводов. Shell-тесты проверяют RAM recovery и403/429 с подменами системных команд. Все APK/IPK и SHA256 проверяются отдельно при упаковке.

Обновляйте приложение/LuCI/RU и ядро вместе. Включённой автомаршрутизации нужен r22. На роутеры эта версия при подготовке не устанавливалась; аппаратная проверка не заявляется.

Команда установки:

```sh
(wget -T 15 -O /tmp/kabanmax-install.sh https://github.com/fefenke/kaban-max/releases/download/0.2.2/install.sh || wget -T 15 -O /tmp/kabanmax-install.sh https://raw.githubusercontent.com/fefenke/kaban-max/0.2.2/install.sh) && KABANMAX_RELEASE=0.2.2 sh /tmp/kabanmax-install.sh --lang ru
```


## 0.2.1

K.A.B.A.N.-MAX 0.2.1 prerelease, ядро 1.14.4-r21.

- Исправлен зависший поиск альтернатив при выключенном автоприменении: обновление домена того же IP больше не мешает завершению проверки, найденная альтернатива сохраняется при новых ошибках исходного маршрута, ошибки задания получают конечное состояние.
- Активная проверка и ожидание очереди отображаются отдельно. После перезапуска старый статус проверки не восстанавливается как выполняющееся задание.
- Direct проверяется перед WARP, по две попытки. Исправлены ложные отказы на HTTP 403/404, сохранены исходные ALPN TLS/QUIC и проверка сертификата; нативный QUIC проверяется аутентифицированным обменом, без навязанного HTTP/3.
- Стабильные IP-записи с накоплением доменов, исправления одиночного/массового применения и ручных действий при выключенном сборе. Применённые IP-маршруты сохраняются до удаления или изменения.
- Реестр независим от ротации журнала; частые изменения хранятся в RAM, flash checkpoint объединяется раз в 15 минут. При отключении питания последние несохранённые изменения могут потеряться.
- Центрированные диалоги, фиксированная ширина таблицы с переносом IPv6, обновление строк без полной перерисовки, исправленные подписи и подсказки. Уплотнён JS и сокращена повторная обработка журналов.

Проверки текущего исправления: воспроизведены три регрессии RED→GREEN; семь пакетов ядра прошли race-тесты из pinned upstream и полной серии patches; 11 frontend-тестов, TypeScript/build/lint; десять APK/IPK проверены на совпадение payload, исходников, версий и собранных ELF; 13 SHA256 записей проверены. Предыдущие полные frontend/backend прогоны не выдаются за повторённые в этом исправлении.

Обновляйте приложение, LuCI/RU и ядро вместе. Автоприменение требует включённой настройки; при выключенной настройке найденные альтернативы остаются ожидающими. Проверка транспорта не гарантирует авторизацию приложения или постоянную доступность удалённого сервера.

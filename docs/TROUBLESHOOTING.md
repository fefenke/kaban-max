# Диагностика по симптомам

Команды на устройстве ниже — справочник, не разрешение подключаться к нему в текущей задаче. Не пересылать полный конфиг/логи без маскирования.

## Приложение не запускается
Сначала версия пакетов/архитектура, статус службы и ограниченный фрагмент `logread -e kabanmax`. Отделить ошибку генерации от готовности sing-box и nft. Сохранить ошибку до перезапуска: restart может уничтожить симптом. Не удалять конфиг из-за одного failed postinstall; проверить состояние пакетного менеджера и конкретный script.

## NFQWS2 готов 1/2, очереди не привязаны
`kabanmax zapret2_status`, `/proc/net/netfilter/nfnetlink_queue`, журнал `kabanmax-zapret2`; сравнить ожидаемые queue/PID с procd. Проверить наличие и загрузку kmod-nfnetlink-queue/kmod-nft-queue, соответствие версии kernel. Затем права +x всех директорий и чтение Lua/fake после сброса привилегий. После этого искать конфликт отдельного zapret2/nft rule. Не устанавливать несовместимый kmod принудительно.

## VLESS timeout / переход на резерв
Зафиксировать время, выбранный outbound, причину primary/confirmation, тип события user dial error vs health failure. При успехах старых потоков новые могут всё ещё не устанавливаться. TCP ESTABLISHED не подтверждает завершённый REALITY и получение ответа назначения. Ping проверяет ICMP, не VLESS. Сравнение через WARP меняет маршрут и добавляет промежуточный узел, потому не доказывает единственную причину. Изменять один параметр, не несколько серверных/клиентских одновременно.

## После переключения основной сразу доступен
Изучить два раунда и probe-only события. Сумма коротких интервалов резерва сама по себе не доказывает, что endpoint не отказывал. Проверить применённые TLS-опции именно конкретного сервера и таймауты. В 0.1.3 свежие первые данные новой TCP-сессии текущего раунда отменяют подозрение; отсутствие такой сессии не считается успехом.

## Подключения/мониторинг недоступны
Проверить процесс ядра и bind адрес Clash API. LuCI по Tailscale и API только на LAN — разные пути. Отличить HTTP auth/secret от connection refused/timeout. Холодные reads через CLI; не открывать WAN в надежде исправить локальную авторизацию. Кнопка «закрыть всё» требует рабочего API и не должна автоматически повторять неизвестный результат мутации.

## WARP endpoint not initialized
Найти предшествующий запрос регистрации Cloudflare API. TLS timeout API может оставить endpoint неготовым после старта WAN. Проверить время/доступность resolver и выбранный путь профилей; это отдельная проблема от VLESS. Не публиковать registration URI/ID.

## Мало памяти или неожиданный reboot
Смотреть MemAvailable, RSS процессов, OOM/kernel log, uptime, трафик exit node и число соединений. APK «MiB in N packages» — суммарная установленная база, а не размер KABANMAX. `df /overlay` — flash, не RAM. GOGC=50 имеет смысл только как измеряемый компромисс RAM/CPU конкретного Go-процесса, не обязательная настройка всех устройств. После reboot старый RAM log может быть утрачен.

## GitHub update error
Проверить HTTP/transport, DNS/fake-IP, сертификат, rate-limit и версию manifests. Не выключать certificate check, не подменять URL непроверенным зеркалом. Сначала сохранить короткий маскированный ответ; общее сообщение не устанавливает причину.

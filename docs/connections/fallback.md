# Fallback

Упорядоченная группа: основной сервер, затем резервы. В новом режиме **Stable fallback** группа опрашивает активный сервер; запасные не проверяются постоянно.

## Подтверждение и переключение

Проверка выполняет HTTPS-запрос через конкретное подключение. Если основной контрольный адрес не отвечает, выполняется подтверждение другим HTTPS-адресом. Только после двух неудач начинается последовательная проверка резервов до первого доступного. Один цикл ограничен 30 секундами. При большом числе кандидатов timeout каждого запроса уменьшается, чтобы зависший префикс списка не блокировал дальние резервы; используйте небольшие группы проверенных серверов.

Ошибки реального открытия соединения используют существующий механизм последовательных попыток: пользовательский запрос не ждёт двух фоновых циклов. Действующие TCP-сеансы не переносятся между VPS. Переключение влияет прежде всего на новые соединения.

## Восстановление

На резерве группа проверяет более приоритетные подключения с отдельным интервалом, по умолчанию **60 секунд**. Для возврата нужны **3 последовательные успешные проверки**; отказ обнуляет счётчик. Пока счётчик не набран, новые соединения сохраняют активный резерв.

Интервал проверок активного сервера задаётся отдельно. Существующие явные значения сохраняются. При простое действует idle timeout, проверки возобновляются по активности. URLTest остаётся отдельным режимом выбора по задержке.

## Настройки

В дополнительных параметрах fallback: Stable fallback, Confirmation URL, Confirmation expected status, Recovery interval, Recovery successes. Адрес подтверждения должен быть другим HTTPS-адресом без логина и пароля. По умолчанию — Cloudflare `/cdn-cgi/trace` с кодом 200. Основной контрольный сайт выбирайте независимо от него.

Ручная фиксация подключения сохраняет существующие правила pin/unpin. Обновление провайдера и остановка группы не должны записывать результаты отменённых проверок в новый состав.

## Что видно в LuCI

Активное подключение, ожидающие резервы, восстановление и последние переключения. История ограничена 32 событиями на группу и хранится в RAM, после рестарта исчезает. Постоянный журнал на flash не создаётся. Ограничение относится к истории групп, а не ко всей памяти sing-box.

Отсутствие WAN отображается отдельно, если NetworkManager умеет его определить. Доступность маршрута сама по себе не доказывает доступность интернета. Когда все кандидаты недоступны, группа не подменяет VPN прямым выходом.

## Ограничения

Это предварительная реализация с автоматическими тестами; нужны испытания на реальной сети. Ошибка проверки не устанавливает виновника: возможны DNS, путь провайдера, сервер VPN и контрольный сайт. Другие группы, подписки или ручная диагностика могут проверять тот же сервер независимо от fallback. Число резервов и секций влияет на ресурсы роутера.

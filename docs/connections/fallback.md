# Fallback

Упорядоченная группа: основной сервер, затем резервы. В режиме **Stable fallback** группа опрашивает активный сервер; запасные не проверяются постоянно.

## Подтверждение и переключение

Проверка выполняет HTTPS-запрос через конкретное подключение. Если основной контрольный адрес не отвечает, выполняется подтверждение другим HTTPS-адресом. После неудачи обоих запросов группа сохраняет выбранный сервер и повторяет проверку после заданной паузы. По умолчанию это 3 секунды; настройка «Пауза перед повторной проверкой» принимает значения от `1s` до `5m`. Пауза отсчитывается после завершения первой пары запросов, время их выполнения в неё не входит.

Если оба запроса снова не прошли, начинается последовательная проверка резервов до первого доступного. Успешная повторная проверка отменяет подозрение на сбой. Если во время неудачного цикла через выбранный сервер открылось новое пользовательское TCP-подключение и получило первые данные, группа фиксирует отдельный сбой контрольных запросов и сохраняет выбор сервера. Просто открытый TCP-сокет, трафик старых соединений и успех из предыдущего цикла не отменяют переключение. Содержимое трафика не анализируется и не сохраняется.

В стабильном режиме новые соединения идут только через выбранное подключение. Ошибка открытия соединения запускает внеочередную проверку его состояния; резерв получает трафик после подтверждённого переключения группы. Действующие TCP-сеансы не переносятся между VPS.

## Восстановление

На резерве группа проверяет более приоритетные подключения с отдельным интервалом, по умолчанию **60 секунд**. Для возврата нужны **3 последовательные успешные проверки**; отказ обнуляет счётчик. Пока счётчик не набран, новые соединения сохраняют активный резерв.

Интервал проверок активного сервера задаётся отдельно. На основном при простое действует idle timeout; на резерве проверки восстановления продолжаются. URLTest остаётся отдельным режимом выбора по задержке.

## Настройки

В дополнительных параметрах fallback: Stable fallback, Confirmation URL, Confirmation expected status, Recovery interval, Recovery successes. Адрес подтверждения должен быть другим HTTPS-адресом без логина и пароля. По умолчанию — `https://cp.cloudflare.com/generate_204` с кодом 204. Сохранённые настройки подтверждения при обновлении не меняются.

Подключение можно выбрать вручную и закрепить в группе.

## Что видно в LuCI

Активное подключение, ожидающие резервы, восстановление и последние переключения. Отдельно показаны неудачные циклы проверок и ошибки открытия обычных соединений, время выбора каждого сервера, число переключений и время на резерве. Время выбора сервера не означает непрерывную доступность всех сайтов.

Подробная история содержит не более 50 событий за последние 24 часа. Сводные счётчики также охватывают скользящие последние 24 часа; до первых суток показывается время с запуска. Для ограничения памяти исторические данные учитываются поминутно: неполная самая старая минута исключается. Длительность текущего выбора ограничивается окном точно.

Всё хранится в RAM. Перезапуск ядра сбрасывает наблюдение; изменение логики группы или её TLS-настроек сбрасывает соответствующую группу. Применение остальных настроек сохраняет сводку при перезагрузке конфигурации в том же процессе.

Причина переключения содержит результат основной и подтверждающей проверок: например `timeout`, `HTTP_403`, `dns_error` или `tls_error`. Ошибка из старого кэша перепроверяется; результаты заменённого подключения не используются для переключения.

# Fallback

Упорядоченная группа: основной сервер, затем резервы. В режиме **Stable fallback** группа опрашивает активный сервер; запасные не проверяются постоянно.

## Подтверждение и переключение

Проверка выполняет HTTPS-запрос через конкретное подключение. Если основной контрольный адрес не отвечает, выполняется подтверждение другим HTTPS-адресом. Только после двух неудач начинается последовательная проверка резервов до первого доступного. Один цикл ограничен 30 секундами. При большом числе кандидатов timeout каждого запроса уменьшается, чтобы зависший префикс списка не блокировал дальние резервы; используйте небольшие группы проверенных серверов.

В стабильном режиме новые соединения идут только через выбранное подключение. Ошибка открытия соединения запускает внеочередную проверку его состояния; резерв получает трафик после подтверждённого переключения группы. Действующие TCP-сеансы не переносятся между VPS.

## Восстановление

На резерве группа проверяет более приоритетные подключения с отдельным интервалом, по умолчанию **60 секунд**. Для возврата нужны **3 последовательные успешные проверки**; отказ обнуляет счётчик. Пока счётчик не набран, новые соединения сохраняют активный резерв.

Интервал проверок активного сервера задаётся отдельно. Существующие явные значения сохраняются. При простое действует idle timeout, проверки возобновляются по активности. URLTest остаётся отдельным режимом выбора по задержке.

## Настройки

В дополнительных параметрах fallback: Stable fallback, Confirmation URL, Confirmation expected status, Recovery interval, Recovery successes. Адрес подтверждения должен быть другим HTTPS-адресом без логина и пароля. По умолчанию — Cloudflare `/cdn-cgi/trace` с кодом 200. Основной контрольный сайт выбирайте независимо от него.

Подключение можно выбрать вручную и закрепить в группе.

## Что видно в LuCI

Активное подключение, ожидающие резервы, восстановление и последние переключения. История ограничена 32 событиями на группу и хранится в RAM, после рестарта исчезает. Причина переключения содержит результат основной и подтверждающей проверок: например `timeout`, `HTTP_403`, `dns_error` или `tls_error`. Ошибка из старого кэша перепроверяется; результаты заменённого подключения не используются для переключения.

# JSON outbound

Подключение, описанное объектом outbound sing-box. Пригодится, если нужного протокола или параметра нет ни в ссылках, ни в туннелях. Поле `tag` обязательно, оно становится именем сервера.

В ядре r9 добавлен отдельный `tls.utls.fingerprint: "chrome_155"`. Обычный `chrome` остаётся Chrome 133. Для ссылок используется `fp=chrome_155`. У профиля 155 есть ограничения ML-DSA и trust-anchor hints: [источники и совместимость](https://github.com/fefenke/kaban-max/blob/main/core/CHROME155.md). В опубликованном r8 этого значения нет.

У отдельного подключения по ссылке отпечаток можно выбрать в его настройках, в поле **TLS fingerprint**. Пустое значение сохраняет выбор из URI; явное значение переопределяет его только для этого подключения, даже если в секции есть другие подключения с таким же URI. Настройка требует ядро с uTLS и поддерживаемое TCP-подключение с уже включённым TLS: VLESS, VMess, Trojan, AnyTLS или HTTPS-прокси. Она не включает TLS сама и не применяется к QUIC, HTTP/3, TUIC или Hysteria. Выбор `chrome_155` требует r9. Для JSON outbound задавайте вложенное поле `tls.utls.fingerprint`, как в примере ниже; UCI-параметр подключения `tls_fingerprint` относится к ссылкам.

```json
{
  "type": "vless",
  "tag": "my-server",
  "server": "203.0.113.10",
  "server_port": 443,
  "uuid": "00000000-0000-4000-8000-000000000000",
  "flow": "xtls-rprx-vision",
  "tls": {
    "enabled": true,
    "server_name": "www.microsoft.com",
    "utls": { "enabled": true, "fingerprint": "chrome" },
    "reality": {
      "enabled": true,
      "public_key": "…",
      "short_id": "0123abcd"
    }
  }
}
```

## Выход без VPN

Так в секцию добавляется и прямой выход через провайдера:

```json
{
  "type": "direct",
  "tag": "Напрямую"
}
```

На дашборде он появится среди серверов секции, и секцию можно будет переключить на прямой выход одним щелчком. URLTest считает его обычным сервером и может выбрать как самый быстрый, поэтому исключите его в фильтре URLTest.

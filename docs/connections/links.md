# URI подключения

Ссылка на сервер в том виде, в каком её выдают VPN-сервисы и панели. Поле принимает такие схемы:

| Протокол | Схема | Сборка ядра |
| --- | --- | --- |
| VLESS, включая Reality, XTLS Vision и XHTTP | `vless://` | все |
| Trojan | `trojan://` | все |
| Shadowsocks, включая Shadowsocks 2022 | `ss://` | все |
| Hysteria2 | `hysteria2://`, `hy2://` | все |
| Hysteria | `hysteria://`, `hy://` | все |
| TUIC | `tuic://` | все |
| SOCKS | `socks://`, `socks5://`, `socks5h://`, `socks4://`, `socks4a://` | все |
| HTTP | `http://`, `https://` | все |
| VMess | `vmess://` | base, full |
| AnyTLS | `anytls://` | base, full |
| TrustTunnel | `tt://` | base, full |
| NaiveProxy | `naive+https://`, `naive+quic://`, `http2://`, `http3://` | full |
| mieru | `mieru://`, `mierus://` | full |

Ссылки `wireguard://` и профили Amnezia `vpn://` добавляются в поле **Туннель**, см. [Туннели](/tunnels/).

## Fingerprint отдельного подключения

Откройте настройки нужного сервера в списке URI подключения. В этом же окне находятся разбиение ClientHello на две TLS-записи и классический обмен ключами для VLESS REALITY. Поле **TLS fingerprint** позволяет отдельно выбрать `chrome_155`, обычный `chrome` (Chrome 133) или другой предлагаемый профиль. Для `chrome_155` требуется ядро 1.14.4-r9 или новее.

По умолчанию выбран **Inherit from connection URI**: сохраняется fingerprint, заданный исходной ссылкой. Явный выбор меняет только TLS-настройку этой записи; URI и имя сервера сохраняются. Настройка привязана к постоянному ID подключения, поэтому переименование сервера или одинаковые URI у нескольких записей не переносят её на соседние записи. Возврат к наследованию снова использует исходную ссылку.

Override доступен для VLESS, VMess, Trojan, AnyTLS и HTTPS-прокси с уже включённым TLS через TCP. Он не включает TLS у plaintext-соединений и не применяется к QUIC, включая XHTTP с единственным ALPN `h3`. Требуется сборка ядра с uTLS. Проверки доступности используют тот же outbound, что и трафик. Отдельная запись URI не меняет серверы внутри подписки.

## Каскадное подключение

Каскад подключается к серверу через другую секцию. Например, провайдер блокирует ваш сервер, а WARP работает. Создайте секцию с туннелем WARP без условий и включите у ссылки **Каскадное подключение** через неё. Без условий секция не забирает ничей трафик и служит только звеном каскада.

Так же работает каскад у [подписок](/connections/subscriptions) и [туннелей](/tunnels/).

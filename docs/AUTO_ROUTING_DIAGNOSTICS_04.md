# ТЗ №04: безопасная часть, 2026-11-15

Актуальное продолжение: [ТЗ №04Б реализовано локально](AUTO_ROUTING_IMPLEMENTATION_04B.md). Описание ниже фиксирует первоначальный read-only этап №04 и прежние ограничения r10; новый opt-in API добавлен отдельным patch, прогноз остаётся read-only.


**Полная автоматизация не реализована.** Есть read-only прогноз в диагностике LuCI и CLI `kabanmax check_route <domain|IP> [LAN-IP|@system] [port]`. По умолчанию порт 443. Операция читает сформированный JSON из штатного `config_path`, не резолвит DNS, не вызывает Clash `/delay`, не пишет UCI и не меняет selector. Прогноз относится к non-DNS TCP; индекс правила начинается с нуля. Это файл конфигурации, а не гарантия того, какой Box сейчас работает.

## Block и порядок

Если Block первым совпал по назначению, устройству и порту, результат — reject; Zapret2 и альтернативы не рассматриваются. Block ниже уже совпавшей секции не выигрывает задним числом. Одно наличие IP в любом Block не означает глобальный запрет по всем источникам/портам. Более раннее неизвестное условие не пропускается ради нижнего Direct.

`predicted` показывает действие, outbound tag и индекс первого доказуемого правила. Тег не выдаётся за стабильный ID секции: generator использует display name. `observed=unavailable`, `verified=not_run, requests=0`. Сопоставляются IPv4/IPv6 CIDR, обычные domain/suffix/keyword, source, port/range, inbound, network и ограниченные logical AND/OR/invert. Неизвестные matcher-ы, regex, SRS, protocol, resolve домена и неполные сведения дают unknown. Отсутствующий источник не считается LAN или System автоматически. FakeIP требует core mapping; сопоставление реальных A/AAAA и CDN не имитируется.

Ограничения прогноза: до 1024 верхних правил, 4096 узлов, глубина logical до 8, до 256 значений одного matcher. При превышении — unknown. Результат никогда не авторизует активные пробы или создание Bypass. Прогноз не доказывает nft/PBR, actual outbound, DNS detour, приложение или фактический egress.

## Архитектурные препятствия и что отложено

В изученном r10 API `experimental/clashapi/proxies.go:getProxyDelay` вызывает `urltest.URLTest`, возвращает только delay, записывает URLTest history и вызывает обновление URLTest groups. `common/urltest/urltest.go:urlTest` выполняет HEAD, закрывает body, не возвращает remote IP, TLS identity и доказательство свежести/ожидаемого результата приложения. `/exit` — фиксированный trace, а не проверка выбранного назначения. Этот API нельзя использовать как независимый checker №04. Это ограничение интерфейса, а не доказанная регрессия r10; ядро не изменено.

Кроме того, `generator.add_combined_route_for_section` создаёт из domain/IP обычные destination conditions. Добавление обоих значений не создаёт безопасного domain AND exact-IP scope. Глобальное IP-исключение для общего CDN-IP недопустимо. Нужен доказанный согласованный путь nft + DNS/FakeIP + core, а не одно поле в managed UCI.

По разрешённому пользователем условию «реализуй только безопасную часть» отложены активные проверки, подтверждение сбоя приложения, предложения, автоприменение, managed-секции, TTL/recheck/rollback и persistent suppression. **Автоматических IP-списков в секциях, включателя автоматики, удаления/очистки автоправил пока нет.** Единственный UI — отдельная диагностика с явным сообщением unsupported. Нет временных правил, которые могли бы остаться активными после expiry/reboot. Нет скрытого Direct, проб с VPS, изменений RU blackhole или ручных списков.

## Продолжение

1. Независимый probe API: pin real IP + SNI/Host, проверенный TLS, ожидаемый status/body/nonce, observed leaf/egress, no redirect/cache, бюджеты и отсутствие записи health. Две свежие попытки; timeout/403/TCP reset отдельно не доказывают отказ приложения. Потребуется новый отдельный проверяемый контракт, не подмена `/delay`.
2. Доказать narrow destination scope без распространения доменного результата на общий CDN-IP при disabled/all/selected pre-resolve, FakeIP, source/port и nft capture. До доказательства возможна диагностика без применения.
3. Затем предложения только server-side, opt-in по Zapret2-секциям, независимый guard кандидатов, UCI ownership/конфликты, TTL/clock/reboot, транзакции и rollback. Ручные записи не меняются.
4. Обязательные списки пользователя: исходная Zapret2-секция — статус, предложения, история, удаление/очистка; Bypass/WARP — отдельное «Добавлено автоматически». Только backend add; UI только просмотр/удаление. Persistent scoped suppression и отдельный сброс. Проверить это локальными интеграционными тестами до аппаратной приёмки.

Согласованные требования — [design](superpowers/specs/2026-11-15-auto-routing-04-design.md); ход выполнения — [план](superpowers/plans/2026-11-15-auto-routing-04.md). Свежие команды и неудачные запуски — [TESTING](TESTING.md). №01–03 и ранее собранный base r10 не пересобирались и не заменялись.

# Реестр автомаршрутизации 0.1.7 / r12

Реализация нового `KABANMAX_0.1.7_development_TASK.md` поверх подготовленного UI v2. Новый документ разрешает необходимые изменения core API и prerelease; прежняя отмена публикации относилась к предыдущему этапу. Устройства и VPS не использовались.

## Хранение и восстановление

- Ожидают: RAM, до 64 последних наблюдений; view объединяет наблюдения и решения в пределах 64 строк. Полного реестра 5000 больше не требуется.
- Применены: отдельный `/etc/kabanmax/auto-routing-applied.json`, owner `auto-routing`, максимум 64 точных scope. Это сохранённые разрешения, **не активные leases**. Ручной Apply отвечает успехом после атомарной записи; при ошибке записи новая lease отзывается, при невозможности точного отзыва запрашивается остановка исходной автоматики.
- Автоматические leases собираются state service раз в 60 секунд, одинаковые данные не переписываются. При внезапном reboot до очередного сбора последняя автоматическая запись может не сохраниться; разрешение не восстанавливается из потерянной RAM. Это ограничение пакетной записи во flash, не обход проверок.
- Исключены: прежний отдельный suppression-файл, атомарная запись сразу при подтверждённом действии. Новые записи ограничены 64. Старый r11-файл с большим количеством исключений сохраняется без обрезания; разрешены явное удаление и уменьшение, рост запрещён. При переполнении показывается предупреждение, bulk selection ограничен 64 ID.
- Общий бюджет: максимум 12 изменений persistent-файлов в минуту, учёт в `/var/run/kabanmax/auto-registry-write-budget.json`, сериализация существующим reload lock. Повтор без изменения данных не пишет flash. При лимите отказ явный, без удаления действующих маршрутов/исключений.
- Повреждение ownership/schema/scope не «чинится» стиранием файла. Генерация конфигурации opt-in отказывается продолжать. Автоматический capture при ошибке отзывает незафиксированные новые grants и сообщает ошибку в UI.

В JSON core передаются saved intents и занятые registry scopes. `New()` не помещает их в leases. Восстановление требует нового наблюдаемого соединения и полного свежего **strict nonce** verifier; target обязан совпадать, срок ограничивается min(новый DNS TTL, исходный Expires). Истёкшие записи, неверный source/owner, future Created, неверный scope и срок сверх 15 минут не дают restore. Занятые постоянными записями слоты не разрешают создать 65-ю запись; освобождение — только после явного удаления и durable update.

Обычный HTTPS после reboot снова требует ручного подтверждения нового предложения. IP-only остаётся диагностикой/точным исключением, но не получает route grant. Наличие файла, TCP dial, соседнего CDN IP или старого успеха не становится доказательством приложения.

## API и операции

Patch `0008-auto-routing-registry.patch` добавляет API version 2: exact source/scope exclude, reset, withdraw и release slot. Старые 0001–0007 сохранены. Core State возвращает весь ограниченный набор решений, без прежнего среза до 20. Runtime leases и observations ограничены 64.

`auto_records` предоставляет source-only поиск, сортировку, страницы по 25 и bounded selection всех подходящих ID текущего фильтра. `auto_action(op=records)` остаётся write-only и повторно проверяет ACL, исходную Zapret2-секцию, ID и eligibility. Пачка максимум 8 ID, recheck только одного свежего flow; frontend не повторяет неизвестный результат записи и оставляет запас transport timeout для bounded worker. Результат содержит done/skipped/failed по ID.

- Apply: только server-owned ещё пригодное предложение; прежние core guards проверяют generation, first-match, DNS/FakeIP, TLS, target, устройства и TTL заново.
- Exclude: durable deny intent перед runtime revoke точного scope. IP без домена допустим к исключению только при установленной исходной секции/устройстве/inbound/порте. Неатрибутированные IP нельзя произвольно приписать секции.
- Remove exclusion: точный runtime reset и сохранение удаления; при ошибке durable update suppression возвращается. Старые решения не активируются.
- Forget saved approval: отозвать соответствующую активную lease, удалить сохранённое разрешение, освободить слот. Ручные UCI-правила не изменяются.
- Массовые операции используют подтверждённый набор ID всего фильтра, включая другие страницы; stale/ineligible ID не подменяются новыми записями. Каждый ID проверяется сервером повторно. Изменение одного scope сохраняет уже проверенные решения других устройств/доменов; незавершённые старые jobs не получают права применить устаревший результат.

## UI и приёмка

Сохранены компактный VPN editor, URI/fingerprint round-trip, выбор WARP без дублей, read-only прогноз и статусы обновлений. Textarea: минимум 6 строк, vertical resize, ограничение ширины и перенос длинных строк. Скрытие пустой auto-вкладки учитывает active CBI fields, а не оставшийся details wrapper. Подсказки используют единый компонент.

Локальные проверки и точные команды: [TESTING](TESTING.md). Аппаратные LuCI themes/Save & Apply, ARM64 runtime, настоящий WARP/VPN/egress остаются UNVERIFIED. Не обещается универсальное распознавание DPI, auto-apply произвольного HTTPS или безопасный IP-only redirect. Изолированные synthetic проверки не подтверждают доступность реальных сайтов.

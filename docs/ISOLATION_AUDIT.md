Проверка соседей фиксирует верхнеуровневые метаданные и hashes отдельных корневых файлов, но не является рекурсивным аудитом чужих проектов.

## Классификация очистки

**А — удалено из рабочего дерева:** только старый игнорируемый результат VitePress `docs/.vitepress/dist/`: 90 файлов, 3 574 909 байт. Предварительно проверено отсутствие tracked files и создан проверенный архив `.local/audit/removed-generated-site.tar.gz`. Полный перечень: `.local/audit/deleted-files.txt`, размеры/SHA-256: `deleted-files.json`. Архив не публикуется. Код и оригинальные изображения не удалены.

**Б — сохранено как исторически ценное:** Git-репозитории, стратегии/конфиги, TLS/TCP-пробы, их исходники и результаты, прошлые release assets, анимационные прототипы и оригиналы, dirty core. Они не импортируются в продукт автоматически. Исторические абсолютные пути в архивных скриптах могут быть устаревшими; это не действующие инструкции.

**В — сохранено до решения:** старые копии зависимостей, неоднозначные дампы/бинарники, ключевой материал и 836 групп совпадающего содержимого вне Git/node_modules. Совпадение SHA-256 не доказывает ненужность: ресурсы, fixtures и разные поколения продукта могут законно совпадать. Не удалять массивно по одному признаку. Ключи не отзывались, роутеры не изменялись.

## Самостоятельность

- `.local/` исключена из Git и Docker context; документированные build/test не используют соседние checkout.
- Приватный helper экспорта core patch исправлен на `.local/core-src` → `core/patches`, вместо старой промежуточной копии.
- В Linux-контейнеры передан только снимок текущих исходников и отдельно чистый архив pinned core. Никаких mount соседнего проекта.
- Разработческий навигатор называется `DEVELOPMENT_INDEX.md`: на Windows `INDEX.md` и существующий VitePress `index.md` совпадают. Пользовательская главная страница сохранена побайтно.
- Верхнерегистровые разработческие документы исключены из VitePress: они содержат относительные ссылки на файлы репозитория, не страницы пользовательского сайта. Их читают в IDE/GitHub.

## Проверки и откат

До переноса: полный файловый manifest, SHA-256, HEAD/refs/status/diff и standalone Git bundles. После: `.local/audit/integrity.json`, свежие тесты в [TESTING](TESTING.md). Состояние index Git может обновиться при status; содержимое staged diff проверяется отдельно.

Для отката расположения сначала сохранить нынешние незакоммиченные изменения. Затем переместить текущий checkout обратно в исходную папку, исторические main/worktree — вместе обратно и выполнить `git worktree repair` с точным путём worktree. Восстановить research и core по таблице; восстановление generated site возможно из tar.gz. Нельзя выполнять обратные moves при занятых именах без проверки. Git bundles/diff — страховка истории, а не автоматический полный backup ignored/private files; сами ignored/private файлы перенесены без удаления.

Все изменения этой задачи локальные. Новый релиз, git push, remote secret scan, live network diagnostics и установка на устройства не выполнялись.

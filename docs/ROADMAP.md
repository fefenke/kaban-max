## Следующие задачи

Задачи №2/3/4, WARP: локально исправлен API detour для прямого режима и автоматической регистрации; no-op и применение обфускации проверены регрессиями. Далее — отдельная приёмка двух профилей, cold boot, временной недоступности API и отсутствия прямого выхода на WR3000S/U по сценариям TESTING. При значимом изменении общего JSON сохраняется Close/Create всего core; endpoint-preserving reload и постоянное хранение полного профиля не реализованы.

Локально выполнено дополнение №12: общий каталог, Chrome 133/155 по семейству/версии, Randomized/QQ/360, совместимость старых алиасов без новых дубликатов. Дополнительные старые версии отложены до конкретного обоснования; доказанного рейтинга устойчивости к блокировкам нет. Полевые тесты требуют отдельного запроса.

Локально после 0.1.5 выполнен вертикальный срез VPN-редактора: VLESS/REALITY и надёжные authority-форматы, эффективный экспорт fingerprint и сохранение ID/порядка. VMess/специальные форматы остаются raw; расширять только по доказанному lossless round-trip. Reload проверен локально на TCP loopback и чистом UPSTREAM+patches; полевой UI/Save & Apply остаётся отдельной проверкой и не считается выполненным.

Опубликована 0.1.5 с r9, отдельным Chrome155 и сохранённым Chrome133: подтверждённые зависимости, patches, TLS/парсер/интерфейсные тесты и ARM64 base/tiny пакеты. Добавлены per-ID отпечатки и единое оформление результатов обновлений. Проверка на устройстве требует отдельного запроса. ML-DSA verification не входит в этот перенос и остаётся ограничением профиля.

Опубликованы в 0.1.4: опциональный резолв перед правилами всех секций, журнал 24 часа / 2 МиБ с очисткой, исправления оформления fallback/конфигурации и явное сообщение об отсутствии обновлений. Live UI и маршруты на устройстве требуют отдельной разрешённой проверки; журнал при экстремальном переполнении системного кольца между опросами — кандидат на потоковый сбор.
1. Проверить сборку с чистого документированного release image: backend test interpreter должен явно присутствовать, все pinned инструменты доступны. Критерий: воспроизводимый frontend/backend/core/package run без ссылок на соседние checkout.
2. Уточнить ошибку проверки обновлений по конкретному HTTP/transport evidence; не обещать устранение провайдерских сбоев. Критерий: отдельный воспроизводимый тест и понятное UI сообщение.
3. По отдельному запросу проверить длительную стабильность fallback на устройстве. Критерий: ограниченный по нагрузке тест с разделением probe-only/user errors, без раскрытия VPS российским назначениям.
4. Вернуться к анимации только после согласования качественного прототипа оригинального персонажа. Трёхчастная TLS-проба также отложена; не включать незаметно.
5. Разобрать сомнительные исторические файлы по частям, сохраняя существенные выводы. Критерий удаления: доказанная ненужность + резервная копия + точный manifest.

Не менять номер продукта и не публиковать релиз ради локальной реорганизации. Результаты текущих тестов могут уточнить приоритет первого пункта.

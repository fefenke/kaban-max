# Возврат прежнего критерия доступности fallback

2026-11-26, прямое указание пользователя после [сравнения0.2.0/0.2.2](FALLBACK_STRATEGY_HISTORY.md). App0.2.3/core r45, append-only0045. Изменяется только общий stable fallback — одинаково для WARP/VLESS и других его участников. Отдельной «старой VLESS стратегии» в r44 не было; решение общей группы уже изменилось в0042 для всех типов. Нестабильный режим fallback и внутренние протоколы профилей не меняются.

Если primary HTTPS проходит, дополнительный URL не проверяется. Если primary не проходит, но независимый confirmation проходит с нужным HTTP status, результат здоровый: сохраняются delay/time успешного confirmation, failed_checks не увеличивается, suspect/confirmed Warn не создаётся и здоровый активный профиль не заменяется резервом. Это прежняя семантика0001, не fake success или TCP-only доказательство. Confirmation TLS/HTTP проверяется прежним coordinator, безопасность не ослабляется.

Если оба URL не проходят, сохраняются подозрение, повторная проверка, подтверждённый Warn и поиск рабочего резерва. Если не проходит никто, сохраняется текущий участник — улучшение0042 не откатывается. Возврат на основной после3свежих успехов; успех независимого URL снова может входить в эту серию. Вето по новым данным текущего раунда восстановлено и не расширено до старых соединений. Одни только старые video sessions не исключают проблему новых подключений. Timer defaults не меняются. Отказ установленного потока не запускает health:0044 сохранён. Общий connection logging, авторутинг, WAN/lifecycle gates не менялись. Счётчики прошлых отказов не сбрасываются этим source change.

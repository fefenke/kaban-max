# Принятые решения

## r12: отдельные bounded intents вместо безусловного восстановления leases

Новый запрос снял требование 5000 и разрешил минимальное расширение core. Выбраны 64 записи, atomic files и bounded write budget; core получает только intent/slot inventory и заново доказывает strict application contract. Ordinary остаётся manual-only. Exact-scope API позволяет убрать отдельное исключение без сброса соседей. [Контракт, trade-offs и условия пересмотра](AUTO_REGISTRY_017.md).

## UI v2: CBI-адаптер и честная граница core

Уточнение 0.1.8: desktop-колонка полей 26em, синие help справа от подписей, без вложенных отступов; компактные стрелки справа. Checked auto-apply доступен для снятия без prerequisites, unchecked включается только при их наличии. Массовое удаление «Применены» использует `forget`, «Исключены» — `remove`, только source/status/search выбранного списка. Утверждено пользователем; [проверки](audits/UI_STYLE_PROPOSAL.md).

Подсказки и layout адаптируют отрендеренные KABANMAX frames; UCI write/load/depends/retain и обработчики остаются LuCI. `auto_records` пагинирует только доступный core snapshot и persistent suppression, с page_size 25/50/100, source filtering и двухсекундным общим read cache. Не эмулировать полный реестр или filtered bulk по обрезанному State; не править persistent suppression отдельно от runtime. Пересмотр — после нового scoped/versioned core API. [Доказательства](audits/UI_FIXES_V2.md).

## 2026-11-16 — ordinary HTTPS не даёт автоматического разрешения

Patch 0007 добавляет web к сохранённому strict. Два транспортных сбоя и два ограниченных TLS/HTTP content успеха альтернативы полезны для ручного предложения, но не доказывают DPI/свежесть/полное приложение. Поэтому web никогда не auto-apply, даже при второй галочке и recheck. Источник имени — только исходный flow/FakeIP, IP — actual dial или единственная original metadata, не DNS batch. Воспроизведённый mixed DNS scope дефект закрыт требованием единственного DestinationAddress до применения lease. Условия пересмотра — только отдельный проверенный application contract/per-address route design; [тесты и границы](AUTO_ROUTING_IMPLEMENTATION_04B.md).


## 2026-11-15 — №04Б: исключение внутри победившего Zapret2

Сохраняем штатный first-match r10. Runtime lease рассматривается после победы исходной opted-in секции и требует exact trusted domain AND real IP AND source/inbound/port. Независимый HTTPS nonce-verifier не использует health/URLTest; только два явных application-failure ответа разрешают проверку альтернативы. Transport/TLS error остаётся inconclusive. Удаление отменяет работу и сохраняет suppression по стабильному section ID в отдельном атомарном файле: запись в UCI могла бы затереть staged ручные настройки. Leases не восстанавливаются через restart без новой проверки. [Доказательства и условия пересмотра](AUTO_ROUTING_IMPLEMENTATION_04B.md).


## ТЗ №04: не использовать delay как доказательство приложения

Read-only forecast работает отдельно от активной диагностики и мутаций. Block рассматривается по порядку и source/port. `/delay` возвращает только задержку и меняет URLTest health; этого недостаточно для автоправила. Не добавлять глобальное CDN-IP исключение вместо domain AND IP. Пересмотреть ограничения только после независимого probe evidence и согласованных scoped route/nft/DNS тестов. [Доказательства и продолжение](AUTO_ROUTING_DIAGNOSTICS_04.md).

## ТЗ №03: границы reload и дискового выбора

Не переносить весь RAM cache на flash ради pins: он содержит также WARP/subscription данные. Новые Box восстанавливают ручные pins из доступного cache, стандартный `/tmp` теряется при boot. Частичный reload общего JSON без разрыва не доказан безопасным: сохраняем Close/Create, pause/readiness и штатное завершение FakeIP. Внешний selector сохраняет прежний interrupt=true; его отдельная UI-опция остаётся необязательной. Пересмотреть при отдельной задаче persistent pins/частичного lifecycle с доказательствами владения соединениями и зависимостей. [Матрица и доказательства](LIFECYCLE_FALLBACK_03.md).

## D13. ТЗ №02: per-address DNS и неизвестные providers

Воспроизведены выход остальных DNS-кандидатов через один Direct route и риск обхода nft при смешанном реальном ответе. Выбраны FakeIP для частичного IP-Bypass, resolve в позиции секции и ограничение кандидатов терминального маршрута. Missing provider не вызывает crash-loop, но удерживает scope через nft pending и core reject до корректного содержимого; guards включаются заново при замене core. Собственные mark-маски не стирают чужие биты. Нужен r10 на прежнем pinned upstream. Цена: неопределимый destination scope секции временно недоступен, lookup необходим даже при выключенном глобальном pre-resolve. Пересматривать по доказательствам реального стенда или при разработке более точной адресной привязки; нельзя заменять fail-closed скрытым Direct. [Доказательства и границы](STARTUP_DNS_DEVICES_02.md).

## WARP API dialer — 2026-11-15

Для native WARP всегда задаём `profile.detour`: выбранная секция либо `direct-out`, включая автоматическую регистрацию. Причина: без detour `protocol/warp.createConfig` использует стандартный Go HTTP transport без core default_mark; nft output может перехватить запрос обратно. Не связываем API с транспортным каскадом, не вводим прямой fallback выбранной секции и не меняем raw JSON. Проверено генератором и offline Go dialer-регрессией. Постоянное хранение профиля на flash и сохранение endpoint при реальном reload не добавлены: это отдельные изменения жизненного цикла/хранения секретов. Пересмотреть при воспроизведённом timeout с корректным detour или отдельной задаче persistent cache.

## D14. Только различные uTLS-профили в новом выборе

Дополнение №12: общие metadata в `shared/tls-fingerprints.json`, TS import + generated ucode с build-check. Истинность проверяется тестами фактического ClientHelloID/handshake/parser закреплённого ядра. Chrome 133 остаётся стандартным, 155 — явным вариантом. Старые chrome_psk/pq-имена в этом ядре являются алиасами 133: не плодим пункты меню, но принимаем старые конфиги без автоматической замены. Пользователь явно отказался от дублирующих профилей. Random (один выбор из трёх браузеров при старте процесса) и Randomized (seeded ClientHello с ALPN) различны и проверены. Старые версии, не предоставленные runtime-ID текущего ядра, не выдаём за рабочие; расширять только при доказанной необходимости совместимости и отдельных ClientHello/handshake-тестах. Проверенного рейтинга версий по устойчивости к блокировкам нет; не подменять его возрастом браузерного профиля.

## D13. Эффективный URI без новой схемы UCI

2026-11-15, задача №9: источник переносимых параметров — `connection_link.uri`, постоянный ID сохраняется. Редактор держит разобранные значения только в JSONMap; перед записью сериализует изменённые компоненты и проверяет совместимость TLS. Отдельный `tls_fingerprint` выше URI по приоритету, экспорт VLESS/Trojan/AnyTLS заменяет fingerprint действующим значением. Непереносимые параметры остаются отдельными UCI-опциями. Непрозрачные форматы остаются raw, без выдуманного round-trip; no-op не нормализует URI. Прямое редактирование произвольного sing-box JSON отвергнуто как изменение контракта/схемы; стандартный URLSearchParams для пересборки всего query отвергнут из-за потери исходного encoding. Синхронизация точных ссылок из D12 расширена на URLTest; алгоритмы групп и подписки не меняются. Расширять список структурированных протоколов только после тестов двустороннего преобразования по pinned parser; перенос override в VMess/HTTPS пока явно не экспортируется.

## D12. Синхронизация точных ссылок Fallback при изменении ручного сервера

2026-11-15: bundle-регрессии доказали, что rename/delete `connection_link` оставляли старые имена в `fallback_level.include_outbounds/exclude_outbounds`. Сохраняем схему UCI и обновляем эти списки на стороне редактора только в своей секции: замена имени на месте, очистка при удалении. Regex, URLTest и фильтры подписок не меняются. Старые связи не восстанавливаются догадочно. Пересмотреть при отдельной задаче перехода ссылок на постоянные ID либо доказательстве аналогичного дефекта в других редакторах. Live reload и все заявленные полевые симптомы этим не подтверждены.

## D1. Один текущий репозиторий и приватный локальный архив
Проблема: несколько поколений исходников, связанный worktree, разрозненные исследования. Выбрано: текущий публичный checkout в корне KABANMAX, старые Git-репозитории и исследования в `.local/`. Истории и неприменённые изменения сохраняются; сомнительные материалы не удаляются. Общие инструменты остаются вне проекта и не являются build-зависимостью. Пересмотреть после точного разбора исторических артефактов; не публиковать архив.

## D2. Подтверждённый fallback вместо немедленного переключения
Проблема: краткие ошибки проб приводили к ненужному выбору резерва. Выбрано: primary URL → другой confirmation URL; после двух неудач пауза `failure_retry_interval` (по умолчанию 3s, 1s–5m), затем свежий повтор. Только повторная неудача запускает проверку резервов. Успех новой пользовательской TCP-сессии с первыми данными текущего раунда может отменить переключение. Dial-only/старые потоки не подходят. Ошибка проверки остаётся в статистике как probe-only. Ограничение: не доказательство доступности всех назначений. Пересмотреть по воспроизводимым ложным переключениям, не только по отсутствию ошибок в логах.

## D3. Пользовательские запросы не переигрываются незаметно
В stable-режиме DialContext идёт в выбранный outbound. Ошибка возвращается приложению и будит health check; повтор запроса может сделать само приложение. Группа не переносит уже открытый TCP-сеанс на другой VPS. Это исключает случайное обращение к резерву каждым пользовательским запросом. Ручные диагностики/дашборд всё ещё могут сами тестировать конкретный резерв.

## D4. TLS-опции на конкретном сервере
Выбрано разбиение ClientHello на две примерно равные TLS-записи с неизменным содержимым handshake; отдельный флаг классического key exchange. Не общий флаг группы, не отдельный прокси-процесс. Проверки используют тот же outbound. Постоянный режим кусками по 512 байт заменён; диагностическое разбиение на три записи отложено. Эффективность у провайдера не гарантирована; менять по одному параметру и сравнивать захват.

## D5. Ограниченная статистика в RAM
Выбран скользящий 24h интервал, 1441 минутный слот на наблюдавшийся сервер и ≤50 событий группы. Старая неполная минута исключается, историческая сводка может недосчитать <60s. Перезапуск/значимое изменение группы сбрасывает наблюдение; неизменённая группа переживает reload в том же процессе. Отдельная кнопка сброса не нужна. Цена: примерно 67.5 KiB/наблюдавшийся сервер плюс прочие структуры, без flash-журнала.

## D6. Холодные чтения dashboard через CLI
Если браузер пришёл через другой интерфейс, прямой Clash API может быть недоступен, хотя LuCI работает. Холодные чтения не ждут 5s direct timeout; CLI возвращает данные, фоновая проба включает direct при достижимости. Мутации сохраняют контроль доступа и не повторяются слепо после таймаута. Длительность живой загрузки после всех установок не измерена в этой задаче.

## D7. Визуальные эксперименты отдельно от продукта
Новые рисунки не соответствовали согласованному оригиналу; анимация/переработка игры отложены. Приватные SVG/Aseprite/превью сохранены, но не часть релиза. Не выдавать движение цельной картинки за полноценную покадровую анимацию.

## D8. Опциональный резолв перед пользовательской маршрутизацией
IP-правило не может сопоставить реальный адрес, если к этому моменту известен только домен/Fake-IP. Выбран явный основной DNS перед пользовательскими правилами с режимами disabled/all/selected; порядок и действия секций сохраняются. Ручные hosts и служебные контрольные домены исключены. Пересмотреть по воспроизводимому конфликту DNS/маршрутов либо серверного sniff.

## D9. Ограниченный журнал приложения в tmpfs
Системный logd может вытеснить сообщения раньше суток. Выбран собственный архив собранных строк на 24 часа по монотонным часам с лимитом сериализованного размера 2 МиБ, сбор каждые 1.5s, ручная очистка через write-RPC. Это не статистика fallback из D5. Flash не используется; перезагрузка очищает архив. Отпечатки вместо старого текста предотвращают хранение удалённых записей в дедупликации. Пересмотреть polling на потоковый сбор, если доказана потеря строк из-за переполнения системного кольца между чтениями.

## D10. Chrome 155 отдельным именем, обычный chrome остаётся 133
Пользователь выбрал сохранение обоих вариантов. Ядро r9 добавляет `chrome_155`, сохраняя Auto/default/legacy chrome aliases. Выбрана закреплённая замена uTLS `Leadaxe/utls-lx@47b8493a47af`, разрешённая Go в точную pseudo-version и checksums; весь sing-box-lx не переносится. Коммит находится после восстановления Chrome133 Auto и до последующих изменений освобождения handshake state. Новый patch применяется после fallback patch, CI включает TLS/парсеры, BSD-лицензия входит в пакеты. Ограничения объявления ML-DSA без проверки таких подписей и trust anchors явно документированы в core/CHROME155.md. Пересмотреть зависимость при включении тех же изменений в основной uTLS или при реализации совместимой ML-DSA verification; не менять default незаметно.

## D11. Отпечаток TLS задаётся отдельному подключению
Явный `connection_link.tls_fingerprint` применяется после разбора URI только к выбранной записи; пустое значение наследует URI. URI, подписки и соседние записи не переписываются. Frontend и backend требуют поддерживаемое TCP-подключение с TLS и доступный uTLS; override не должен молча включать TLS или попадать в QUIC/HTTP/3. Основание — отдельный выбор пользователя без изменения остальных подключений. Проверки включают совпадающие URI с разными настройками; пересмотреть список протоколов только после подтверждения поддержки в парсере и ядре.

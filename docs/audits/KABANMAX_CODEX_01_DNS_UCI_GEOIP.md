# Чат 01 — корректность DNS, сохранения UCI и GeoIP/Bypass

> **ВАЖНО — фильтр версий.** KABANMAX архитектурно основан на Forkop **2.0**, а НЕ 1.0.5. В Forkop 2.0 (релиз 27.10.2026) используется собственное ядро `sing-box-forkop`; встроенные Zapret/Zapret2/ByeDPI удалены. В KABANMAX — собственное ядро `sing-box-kabanmax` и заново интегрированный Zapret2. Репорт или PR для 1.0.5 **не доказывает** наличия дефекта в 2.0/KABANMAX. Сначала сравни реально затронутый механизм в локальной версии и воспроизведи тестом. Если проблема старой архитектуры отсутствует — пометь «неприменимо» и **не изменяй код**. Источники: [Forkop 2.0.0](https://github.com/ushan0v/forkop/releases/tag/2.0.0), [Forkop 1.0.5](https://github.com/ushan0v/forkop/releases/tag/1.0.5), [`VERSION_AUDIT_FORKOP_2_0.md`](VERSION_AUDIT_FORKOP_2_0.md). Статус issue `closed` и PR `closed` не равен «слит» или «попал в релиз»; в `main` Forkop 2.0 проверены исходники на коммите `129d303` (02.11.2026). Локальный KABANMAX новее публичного GitHub `main`, поэтому **истина — локальный код**.


**Приоритет:** P0. **Цель:** закрыть подтверждённые риски неправильных DNS-ответов и неверного прямого маршрута без регрессий WARP/REALITY/Fallback.

## Задачи одним пакетом

1. **Пропадающие `config_path`/`cache_path` при Save & Apply** — сравни `fe-app-kabanmax/src/kabanmax/tabs/settings/form/service.ts`, `kabanmax/files/usr/lib/singbox/runtime.uc`, начальный `kabanmax/files/etc/config/kabanmax`. Добавь безопасные значения по умолчанию **в backend**, не полагаясь на запись LuCI; при этом явно заданные пользовательские пути нельзя перетирать. Покрой отсутствие UCI-опций, сохранение значений равных default, миграцию и повторное сохранение. Референс: [Forkop issue #160](https://github.com/ushan0v/forkop/issues/160) — **автор написал, что исправил**; в `main` у него уже есть `singbox/constants.uc::config_path()` с fallback `/etc/sing-box/config.json`, несмотря на отсутствие `forcewrite` в LuCI. Не копируй слепо, проверь оба пути.

2. **DNS через выбранную секцию не должен возвращаться на прямой bootstrap для обычных доменов**. Исследуй `kabanmax/files/usr/lib/singbox/dns.uc::default_domain_resolver()` и `singbox/generator.uc`. Сейчас в опубликованном коде при `dns_detour_enabled=1` выбран bootstrap. Раздели резолв **адресов инфраструктуры** (VPN/DNS endpoint, bootstrap) и **обычных доменов назначения** (пользовательская политика DNS). Учитывай порядок запуска, отсутствие DNS-циклов и блокировки/подмены UDP:53. Тесты должны охватывать detour on/off, DNS сервер по IP/домену, нерабочий VPN, IPv4/IPv6, FakeIP и fail-closed для защищённых направлений. [Issue #166](https://github.com/ushan0v/forkop/issues/166) — **открыт, решение пользователя описано, автор не исправил**. Замена `default_domain_resolver` одной строкой — **не готовое безопасное решение**, она может вызвать циклическую зависимость.

3. **GeoIP SRS / Bypass / DNS-правила**. Проверь, не попадает ли IP-only или смешанный `rule_set` в DNS-правила запроса без правильного ограничения; проверь, что IPv4/IPv6-подсети действительно влияют на Bypass до FakeIP и не нарушают обычные доменные правила и приоритеты секций. Не делай предположения, что `rule_set_domain_only` решает всё. Референсы: [issue #153](https://github.com/ushan0v/forkop/issues/153) (**действительный регрессионный кейс Forkop 2.0 после миграции с 1.0.5; автор заявил об исправлении, `main` 2.0 содержит `rule_set_domain_only` для каждого DNS `rule_set`, но это не означает полного решения Bypass**), [PR #156](https://github.com/ushan0v/forkop/pull/156) (**закрыт без слияния**, подробное предложение с `evaluate`/`match_response`/`respond`, проверено автором PR), [код Forkop](https://github.com/ushan0v/forkop/blob/main/forkop/files/usr/lib/singbox/generator.uc). Используй совместимые с текущим ядром sing-box-kabanmax конструкции.

4. **Только регрессионная проверка 2.0: согласованность nftables ↔ sing-box для community IPv4/IPv6**. В `nft/ruleset_sync.uc`, `nft/sections.uc`, `singbox/generator.uc`, `singbox/rulesets.uc` сопоставь список захваченных IP и правила маршрута; никакая подсеть не должна попадать в TPROXY с последующим неожиданным `direct-out`. Минимальный тест: Telegram, Discord, Meta, произвольный смешанный SRS, IPv6-only и IP-literal без DNS. [Issue #126](https://github.com/ushan0v/forkop/issues/126) — **исторический случай Forkop 1.0.5, НЕ подтверждённый в 2.0**; заявитель нашёл решение в Trafira. Система 2.0 использует иной `nft/ruleset_sync.uc`. Если тест в KABANMAX проходит, не изменяй механизм ради этого старого issue.

## Критерии приёмки

- Пропавшие UCI-опции не мешают старту и не стирают явный пользовательский выбор.
- Доступность VPN не зависит от случайных прямых DNS-подмен, нет DNS-петель.
- DNS/GeoIP Bypass и route-правила соблюдают порядок, ограничения по устройствам и семейство IP.
- Тесты специально ловят возможный уход перехваченного IPv6 в `direct-out`.
- Только целевые тесты изменённых компонентов; отмечай непроверенные сценарии реального провайдера.

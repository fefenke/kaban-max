**Исторический отчёт этапа UI v2.** Следующее принятое ТЗ разрешило core API и prerelease 0.1.7, отказалось от 5000 IP; exact reset/bulk и хранение реализованы в r12. Актуальные границы: [AUTO_REGISTRY_017](../AUTO_REGISTRY_017.md). Отмена публикации и блокеры ниже относятся к предыдущему этапу, а не к новому запросу.

Публикация отменена последним указанием пользователя. Коммиты, push, теги и новый release не создавались. Версия приложения не повышалась, пакеты 0.1.6 не заменялись. Изменения подготовлены поверх исходного dirty tree; существующие исправления сохранены.

## Что не реализовано и почему

1. **Полный живой реестр 5000 записей.** `core/patches/0006-auto-routing.patch`, `Manager.State()` сокращает кандидатов до 64, решений до 20, историю до 30; leases и внутренние бюджеты также ограничены. Backend-адаптер безопасно пагинирует полученный снимок и явно сообщает об ограничении. Синтетический тест 5000 доказывает пагинацию адаптера/DOM, а не ёмкость ядра. Нужен новый scoped read API с полными per-source counts; переписывать core 0001–0007 этим ТЗ запрещено.
2. **«Применить все» / «Исключить все» по всему фильтру.** Нет полного snapshot/version и серверного batch-контракта; `Revoke()` не исключает произвольный ещё не проверенный candidate. Не реализована фиктивная операция над только видимой страницей. Нужны полный scoped snapshot и bounded transactional/batch API с partial results и повторной проверкой ID.
3. **Удаление одного исключения или исключений по поиску.** Runtime `reset` умеет только целую исходную секцию. Правка одного persistent JSON без синхронного узкого runtime reset создала бы рассогласование. Разрешён только существующий reset всей секции при пустом поиске; кнопка заблокирована при фильтре. Требуется exact-scope reset API ядра.
4. **IP-only auto-apply и auto-apply обычных сайтов.** Без доверенного domain/flow нельзя безопасно перенаправлять общий CDN IP. Обычный HTTPS не имеет strict nonce application contract. Контролы честно ограничены; новый verifier/attestation contract и transport/routing изменения не выполнялись.
5. **Полная визуальная приёмка каждого экрана на настоящем LuCI и всех темах.** Локальный headless использует структуру CBI, сверенную с [официальным form.js](https://github.com/openwrt/luci/blob/master/modules/luci-base/htdocs/luci-static/resources/form.js), и наши scoped styles. Он не загружает установленную на роутере тему. Нельзя считать полностью проверенными все выпадающие меню/варианты тем, стек модалок, аппаратный Save & Apply, физический egress и ARM64 runtime. Это отдельная приёмка, не доказанный технический дефект.

Условия пересмотра backend-ограничений: отдельное согласование изменения core API, затем тесты version/scope/ACL/TTL/CDN isolation/перезапуска и исполняемая приёмка нового ядра. Прежние бюджеты, fail-closed, DNS/nft/PBR и transport не ослаблялись.

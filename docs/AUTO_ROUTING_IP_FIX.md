# Локальное исправление IP/секции и журнала — 2026-11-16

Статус: опубликован [**0.2.0 prerelease / r14**](https://github.com/fefenke/kaban-max/releases/tag/0.2.0), tag/source `42937680d66c03788975f7362a2e41fd4e1a6741`. Установки на оборудование не было. Новый core patch `0010-concrete-ip-section-routing.patch` требует r14 при включённой автоматике; без неё минимум r10 сохранён.

## Подтверждённые причины

- `ReportDial` записывал адрес только успешного подключения. При полном отказе A/AAAA `Observe` оставлял IP пустым, хотя `net.OpError.Addr` содержал адрес ошибки. Web verifier завершался с `actual_destination_ip_unknown`.
- Уже принятая domain/IP lease отвергалась при нескольких разрешённых адресах до конкретного dial. Теперь индивидуальные dial проходят scoped selection отдельно; здоровый соседний IP не перенаправляется.
- Независимое pre-release ревью нашло два дефекта первой реализации: общий event сохранял lease от проигравшего IP и generic wrapper скрывал optional interface/network dial методы. Выбор перенесён в hooks Direct, outer parallel/family racing сохранён. Каждая попытка имеет private event; только итоговый conn/error передаёт его в основной event. Original sibling не наследует alternative lease; отменённый racer не меняет победителя. Проверяются и network strategy/interface types/fallback delay.
- Backend требовал валидный шестикомпонентный scope даже для `dismiss`, который удаляет ошибку по аттестованному ID. Поэтому строки без IP оставались с `unattested_scope`. Для dismiss сохранены source/ID/status/search проверки; разрешения маршрутизации он не меняет.
- Журнал каждый раз вычислял отпечатки всего неизменившегося дампа внутри RPC. На синтетических 10 000 строк (~1,2 МБ) исходная обработка после clear заняла 3880 мс в локальном контейнере. Это подтверждённый дефект производительности, но не доказанный единственный диагноз живого роутера.

## Поведение

Ошибка относится только к выигравшей Zapret-секции. Фактический IP берётся из структурированной ошибки dial, а не произвольно из DNS или текста. Проверки сохраняют порядок: две попытки исходного Zapret, затем две Direct при разрешении, затем настроенный выход выбранной секции WARP. Две повторные одинаковые реальные ошибки того же scope за час могут подтвердить исходный сбой вместо inconclusive/отключённой повторной пробы; старое или другое сообщение не подтверждает новый сбой. Успешная повторная проверка исходного пути сохраняет его. Первый проверенный вариант становится явным предложением. Если рабочих вариантов нет, выводится конкретный результат вместо общего текста без объяснения.

DNS подтверждает пару домен/IP. Если связи нет, в ordinary web режиме запись переходит в IP-only scope; исходный домен остаётся только контекстом перепроверки original first-match. Ручное IP-only предложение не требует auto-apply галки. Для автоматического принятия IP-only отдельная вложенная галка остаётся обязательной. TLS/HTTP/content, инфраструктурные ограничения, устройство, inbound, порт, TTL и source ownership сохраняются. IP-only HTTPS по-прежнему требует валидного сертификата IP; универсальные UDP/произвольные протоколы этим изменением не реализованы.

Выбирается **секция**, а не её внутренний WARP-профиль. Её выход используется как настроен (в том числе fallback), без применения списков адресов целевой секции. Доступны секции с проверяемым WARP-графом: selector/fallback/urltest допускаются только с WARP-листьями без VPN detour. VPS/opaque providers/mixed Direct группы не становятся WARP автоматически. Старая настройка профиля сопоставляется с родительской секцией; сохранение нового выбора удаляет старый ключ, чтобы очистка выбора не включала legacy профиль обратно.

UI показывает название предложенной секции или Direct; до предложения — исходный выход. Вложенный флаг сдвинут вправо, стрелка убрана, дополнительные параметры отделены от реестра. Техническая строка `automatic_routing_unavailable` убрана из списка; недоступные действия остаются отключёнными. Подтверждение операций — стилизованный HTML dialog с Cancel/действием, без browser confirm и без замены несохранённой формы LuCI.

## Журнал

Неизменившийся дамп сравнивается нативно и не хешируется повторно; cache остаётся только в RAM и не попадает в архив дедупликации. `ord(line, index)` убирает выделение подстроки для каждого байта. После изменения повторная обработка того же синтетического дампа после clear заняла **2 мс**, первая обработка — 2856 мс.

Этот раздел описывает прежний этап оптимизации. Текущие меньшие byte/object/input/RPC лимиты и evidence расхода RAM заданы в [LOGGING](LOGGING.md); прежние 1000 строк/2 МиБ больше не являются текущим контрактом.

`log_text` передаёт текст частями, не разрезая UTF-8; текущий размер страницы — в LOGGING. Продолжения используют снимок одной revision, а успешная очистка инвалидирует его. Frontend собирает только полную revision, один раз начинает заново после reset и не возвращается к системному кольцу после clear. RPC отправляется отдельно от batch, timeout 15 секунд. Это не аппаратная приёмка.

Пустой журнал с начальной revision/cursor=0 возвращает текст, а не `unchanged`. Frontend также умеет один раз запросить полный ответ с cursor=-1, если `unchanged` пришёл без локального cache: иначе новая страница могла постоянно показывать «Не удалось загрузить логи».

## Проверки

RED до реализации: новые Go сценарии теряли actual IP, возвращали DNS/identity отказ; WARP fallback не принимался. Backend dismiss без IP давал done=0; выбор секции игнорировался. Frontend не имел route/reason formatter. Большой журнал возвращался одним ответом; frontend обрывал чтение на первом chunk.

Свежие команды и итоговые результаты записаны в TESTING. Локальное ядро проверялось на имеющемся Go **1.25.10**; CI на закреплённом **1.26.10** также прошёл: [run](https://github.com/fefenke/kaban-max/actions/runs/43949270446). Network-none binary scenario использует только documentation IP, synthetic TLS и отдельную nft table контейнера. Публикация 0.2.0 подтверждена; роутеры/VPS и установка на оборудование не использовались.

Промежуточные frontend-прогоны выявили несинхронизированный PO/POT, тип unknown при записи UCI и старый bundle после остановленной TypeScript сборки. После исправления типа и успешной пересборки один regression ожидал undefined вместо фактического UCI null; исправлено ожидание, а не API. Повтор browser matrix со старым фиксированным профилем получил stale DevTools port; проверка повторена с новым изолированным профилем. Локальным образам не хватало одновременно Go/Python/nft/OpenSSL: использованы имеющиеся образы, стандартный Go certgen и перенос только локальных nft runtime-библиотек в ignored task tools, без установки пакетов/сети.

# Известные проблемы и степень подтверждения

## 0.1.9 / r13 в подготовке

Воспроизведены ошибки 0.1.8: подмешивание WARP/unattributed, no-progress вместо ошибки, однократно снимаемый auto-apply, постоянный readonly IP-only, лишние JSON/счётчики и пересоздание строк. Исправления и новые logged-error/scoped web/IP TLS проверки — в [контракте](AUTO_ROUTING_019.md). Физическая LuCI/egress приёмка остаётся открытой. IP-only без проверяемого HTTPS не получает разрешение; strict domain-контракт сохраняет свои ограничения. Прежние ordinary manual-only пункты ниже — история r11/r12.

## 0.1.7 / r12

Прежние r11-блокеры exact reset/bulk закрыты новым API. Списки ограничены 64; legacy suppression сверх лимита сохраняется для явного сокращения. Автоматический capture пакетный (60 с): внезапный reboot может потерять последний ещё не зафиксированный intent; ни одна сохранённая запись не становится активной без новой проверки. Ordinary HTTPS/IP-only не получили недоказанное auto-apply. Аппаратная LuCI/theme/ARM64/egress приёмка остаётся UNVERIFIED. [Условия и ограничения](AUTO_REGISTRY_017.md).

## UI v2: границы r11 и визуальной приёмки

Core State сокращает candidates/decisions/history до 64/20/30; новый серверный `auto_records` не может восстановить отрезанные записи. Полный per-source реестр и filtered bulk требуют нового API. Runtime reset поддерживает целую исходную секцию, но не отдельное suppression: UI разрешает полный reset только без поиска и с подтверждением. IP-only применение и generic HTTPS auto-apply не реализованы и не обещаются. Все темы/меню/модалки живого LuCI остаются непроверенными. [Доказательства и условия пересмотра](audits/UI_FIXES_V2.md).

Выпущенный 0.1.6: скрытый результат проверки обновлений приложения и неактивные кнопки автосписка подтверждены на уровне LuCI attribute semantics и regression tests. Исправлены локально через DOM properties, bundle пересобран; новый пакет ещё не опубликован. Подробности — TESTING.

## Приёмка 0.1.6, 2026-11-16

Локальные release gates PASS; аппаратные logread/TZ, LuCI, NFQUEUE/PBR/mwan3, WARP/VPN egress, DNS/Direct leaks и ARM64 runtime — UNVERIFIED. Выпуск допустим только как prerelease. Синтетические HTTPS-пробы не доказывают DPI-блокировку или работоспособность целого приложения. Проверки миграции/rollback используют mocks, установка пакетов на OpenWrt не выполнялась. [Свежие результаты](TESTING.md).

## №04Б-ФИНАЛ, 2026-11-16

Ordinary HTTPS теперь работает без nonce, но только как manual proposal по ограниченному ответу; универсального auto-apply для чужих приложений нет. Без доверенного FQDN — TCP diagnostic без Apply. При полном отказе dial нескольких A/AAAA actual IP может остаться неизвестным; при неоднозначном DNS lease не выбирает адрес за исходный dialer. Небольшое тело <32 bytes, неподдержанный content type, CNAME, cached/anti-bot/auth/rate-limit и неполный route context остаются inconclusive. [Актуальный контракт](AUTO_ROUTING_IMPLEMENTATION_04B.md); прежний пункт ниже «только nonce» относится к состоянию 2026-11-15.


## №04Б: границы локально реализованной автоматики

Автоматизация требует r11 и сотрудничающий HTTPS nonce endpoint. Произвольные сайты, CNAME, неполный process/interface context, opaque инфраструктура и динамические subscriptions не подтверждаются. IP-only сохраняется, но unknown identity не разрешает перенаправление. Runtime reset/stop требуют доступного API; permanent stop — выключение opt-in с Apply. Physical egress/NFQUEUE/PBR и настоящий provider WARP требуют отдельной аппаратной проверки. Это намеренные fail-closed границы; не исправлять их fallback на обычный HTTP 200 или глобальный IP-Bypass. [Подробности](AUTO_ROUTING_IMPLEMENTATION_04B.md).


ТЗ №04 реализовано частично: доступен только прогноз, не автоматический подбор или IP-списки в секциях. r10 delay API не выдаёт требуемое доказательство приложения/IP/egress и изменяет health. Narrow CDN scope ещё не доказан; unknown SRS/resolve/device данные не заменяются Direct. [Условия продолжения](AUTO_ROUTING_DIAGNOSTICS_04.md).

ТЗ №03: стандартный `/tmp/sing-box/cache.db` не переживает reboot, поэтому ручные pins холодную загрузку по умолчанию не переживают. Дисковое восстановление с явным persistent cache проверено локально; flash/power-loss — полевая приёмка. Общий JSON reload закрывает старые TCP, хотя обычный Fallback switch их сохраняет. r10 base собран отдельно, ARM64 только кросс-собран. [Граница и проверки](LIFECYCLE_FALLBACK_03.md).

ТЗ №02, 2026-11-15: смешанный IP-Bypass сохраняет FakeIP; resolve в позиции секции и ограничение dial-кандидатов защищают остальные адреса. Missing provider удерживает source/port scope через nft pending и core fail-closed. Без device-ограничений отказ может затронуть весь неопределимый destination scope секции до первого содержимого; явные исключения и более ранние правила сохраняются. Нужен локальный r10. Предупреждение №01 ниже о непроверенном смешанном ответе — историческое. Оставшиеся cache/kernel/VPN проверки: [ТЗ №02](STARTUP_DNS_DEVICES_02.md).

Неисправленное/непроверенное: полноценная анимация и новый дизайн игры; фактическая причина периодических таймаутов отдельного провайдера; поведение текущих живых серверов. Не превращать гипотезу DPI, MTU, VPS или OOM в доказанный диагноз.

Журнал приложения хранит уже собранные строки независимо от дальнейшего вытеснения из logd. При переполнении системного кольца между опросами (1.5s), недоступности state service или перезагрузке сбор не гарантирует сохранность всех сообщений. Перезапуск самого state service сохраняет архив в `/tmp`. Возраст считается с момента сбора, исходная строка не переписывается. Это ограничение polling, а не проверенная потеря на живом роутере.

Аудит переносит код без изменения сетевых алгоритмов. Проблемы сборочного окружения и результаты свежих тестов фиксируются в TESTING и локальном отчёте, а не скрываются за историческими зелёными тестами.

## Локальное исправление после r13

Потеря IP при mixed A/AAAA, `unattested_scope` при dismiss, отсутствие выбора секции и тяжёлое чтение после clear разобраны в [отчёте](AUTO_ROUTING_IP_FIX.md). Аппаратный диагноз постоянного отказа log_text не подтверждён; локальные регрессии не заменяют проверку установленного комплекта. IP-only без валидного IP TLS/content и неизвестные протоколы не получают Apply. Сбор журнала ограничен 1000 строками за опрос; свежая полная потеря >1000 строк требует streaming-сборщика.

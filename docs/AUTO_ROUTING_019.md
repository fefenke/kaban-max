# Автомаршрутизация 0.1.9 / r13: сначала ошибка

## Обязательный порядок

Пользователь уточнил поведение после 0.1.8: сначала реальная ошибка соединения в журнале, затем проверка её принадлежности выигравшей Zapret-секции, затем проверка разрешённых альтернатив. Без обоих подтверждений запись не рассматривается и не показывается в списке секции. Ошибка WARP не становится ошибкой META.

Удалены обход `/connections`, выводы из отсутствия скачивания и подмешивание `unattributed` в единственную opted-in секцию. Core хранит до ошибки только контекст конкретного соединения, без счётчиков/списка наблюдений. При настоящей ошибке пишет строку с ID и сохраняет тот же ID в `failure`. Нормальное закрытие/отмена не допускаются. Выключенный журнал или уровень, подавляющий Error, не дают кандидатов.

Ошибка уже перенаправленного Direct/WARP обрабатывается отдельно: в журнале указан фактический outbound, отзывается только lease ID этого соединения; она не создаёт новый «исходный сбой Zapret». Поздний сбой старого соединения не отменяет заменяющую lease.

## Проверка и разрешения

Главный флаг включает обработку ошибок. Direct/WARP задают разрешённые альтернативы. Отдельный «Автоматически применять» разрешает автоматическую установку проверенного маршрута. Под ним находится IP-only. Переключение не блокирует последующие клики; настройки сохраняются обычным Save & Apply.

Обычный HTTPS после реальной ошибки может автоматически получить ограниченную lease только при явном opt-in, двух transport failures исходного маршрута и двух TLS/HTTP/content успехах альтернативы. Сохраняются проверки сертификата, кода/типа/содержимого ответа, anti-bot/cache guards, повторный first-match, точный IP/domain/device/inbound/port, DNS/TTL, инфраструктурные исключения и бюджеты. Это не доказательство DPI или работоспособности всего приложения; строгий nonce-контракт не подменяется обычным ответом.

IP-only требует отдельного разрешения, HTTPS-ответа и валидного сертификата для самого IP. Нет обратного DNS или придуманного имени; один TCP dial не даёт разрешения. Такая lease не применяется к трафику с известным доменом, другому IP/устройству/порту/секции. Для IP-only нет безусловного восстановления из файла. Явно настроенный strict domain-контракт остаётся ограничением; IP-only не отменяет его.

Registry API version 3 добавляет `registry_dismiss`: удалить текущую ошибку/решение, не создавая постоянного исключения. Backend повторно проверяет source/status/search и ID. Активная автоматика требует r13; при выключенной общий minimum остаётся r10. Старые 0001–0008 сохранены, изменения поставляются отдельным `0009-error-driven-auto-routing.patch`.

## Интерфейс

Нативная колонка LuCI Bootstrap 180px и промежуток 20px, подписи/вопросики вправо; добавленная высота строк убрана. [Исходные стили LuCI](https://github.com/openwrt/luci/blob/master/themes/luci-theme-bootstrap/htdocs/luci-static/bootstrap/cascade.css). Заголовок списка остаётся слева. На узких экранах поля переносятся.

Пагинация — обычные номера и стрелки с текущей страницей, без дробей и диапазонов; при одной странице блока нет. Ориентир — [стандартная нумерованная пагинация](https://design-system.service.gov.uk/components/pagination/). Одинаковый ответ не пересоздаёт строки и не показывает Loading; открытые сведения об ошибке сохраняются. Неизвестный маршрут не подписывается «Zapret2». Вместо JSON показаны ошибка, время и краткие результаты проверок, без дополнительной колонки исходной секции. У pending есть удаление; Apply требует положительного решения проверки.

## Свежая проверка и границы

- RED backend: одна opted-in META ошибочно показывала `video` из `unattributed`; после исправления остаётся только собственная ошибка. Проверены также противоречивые source ID/outbound, здоровые и чужие записи.
- RED browser: auto-apply становился недоступным; исправлены повторные клики и зависимость IP-only от родительского флага. Матрица **320/375/768/1280 + dark 375** прошла с официальным CSS Bootstrap; сохранены детали/DOM при неизменном ответе, номера страниц, скрытие одной страницы, операции удаления.
- Чистый pinned upstream + девять patches: `tests/core/run_auto_routing.sh` с Go **1.26.10**, `-race` — PASS для `common/autoroute`, `route`, `experimental/clashapi`, `protocol/group`, `experimental/cachefile`. Тесты включают source/log proof, отсутствие no-progress, explicit web auto-apply, IP SAN certificate/content, TLS rejection, exact scope и rollback старого/замещающего соединения. Замечание независимого ревью об ошибке альтернативы исправлено отдельной веткой без ложного исходного кандидата.
- Собран x86_64 r13. В `--network none` контейнере с NET_ADMIN выполнен `python3 tests/core/auto_error_binary.py <binary> <synthetic-fixtures> <tools>`: WARP-ошибка не попадает в META, ID кандидата найден в журнале, dismiss не меняет разрешения; без журнала/без ошибки нет записей; автоматический Direct фактически передал содержимое приложения. IP certificate проверен unit/integration-тестами Go, не этим executable-сценарием.
- Frontend: `npm.cmd run build`, `npm.cmd run lint`, `npm.cmd test -- --run` — **176/1686 PASS** до последнего уточнения текста/нативной геометрии; окончательный повтор и GitHub CI обязательны перед выпуском. Первые повторы нашли устаревшие PO/POT строки; правильный порядок — build, locales, tests.
- Backend после r13-validator: **91/92**, единственное старое ожидание package r12 обновлено на r13; окончательный полный прогон выполняется CI. Предыдущий полный backend-прогон новой логики до этого обновления minimum был **92/92**. Эти два прогона не выдаются за один.
- Местная упаковка ARM64 прервалась из-за заполнения C:, затем Docker получил I/O ошибки своего хранилища. Удалены только созданные этой задачей воспроизводимые raw builds/browser profiles и побайтно проверенные дубликаты загрузок; сохранены пакетный комплект 0.1.8 и отчёты. Локальные r13-пакеты не сертифицированы для публикации; окончательная сборка и payload inspection перенесены в существующий GitHub Actions. Системный Docker и чужие данные не изменялись.

Ignored evidence: `.local/audit/auto-routing-repair/`, в том числе `browser-matrix.json`, `repaired-desktop.png`, `repaired-mobile.png`. Скриншоты используют реальные descriptors/renderer/адаптер и нативный CSS на синтетических данных, а не установленную тему роутера.

Устройства/VPS/физические WARP/VPN/egress не использовались. Универсальная маршрутизация произвольного UDP/не-HTTPS IP-only не обещается. Опубликовать можно только после успешных CI, новой сборки пакетов и проверки точных опубликованных bytes; пользовательское разрешение публикации сохраняется.

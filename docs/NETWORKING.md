# Сеть и границы ответственности

## №04Б-ФИНАЛ

Web probe закрепляет только фактический IP одного потока и его достоверный FQDN; не перебирает DNS siblings. TCP-only diagnostic не доказывает HTTPS/UDP и не создаёт IP-wide lease. Для scoped применения original matcher обязан уже выбрать один exact адрес. Generic web результата хватает только для ручного подтверждения; physical egress остаётся неизвестным. [Критерии](AUTO_ROUTING_IMPLEMENTATION_04B.md).


## Автоматические маршруты №04Б

Опциональный r11 Manager не меняет порядок секций/nft и не создаёт глобальный Bypass. Только реальный first-match Zapret2 допускает точную domain/IP/source/inbound/port lease. Fresh DNS+TTL, исключения устройств/System, endpoint protection и независимые Direct/WARP permissions проверяются отдельно. Physical egress не подтверждается из одного adapter/mark. [Полный контракт](AUTO_ROUTING_IMPLEMENTATION_04B.md).


ТЗ №04: [read-only прогноз](AUTO_ROUTING_DIAGNOSTICS_04.md) читает generated route rules; неизвестные условия останавливают сопоставление. Block действует как первое совпадение с учётом source/port. Прогноз не доказывает nft/PBR, DNS/реальный IP, active leaf или egress и не разрешает Direct. Автоматическое изменение маршрутов пока недоступно.

## Перехват и маршруты
`core/constants.uc`: nft table `KabanMaxTable`; FAKEIP mark `0x04000000`, outbound mark `0x08000000`, router mark `0x10000000`. Запрет2 использует отдельную базу `0x02000000` с идентификатором секции и очередями 4300–4555. Не забирать эти биты под стороннюю политику.

`nft/apply.uc`: mangle prerouting −149, mangle output −150, Zapret2 reply prerouting −151; proxy prerouting −100. DNS redirect priority −101 расположен перед обычным системным −100. Policy rules с priority 105 маршрутизируют перехват, отдельные проверки source-mark учитывают поведение Tailscale. Точные правила зависят от сформированной конфигурации — числа не повод добавлять такие правила вручную.

Сначала генератор применяет служебные sniff/hijack-DNS и правила исключений, затем пользовательскую политику секций. `singbox/route.uc` устанавливает final direct и outbound mark; `default_interface` задаётся только явной настройкой. Автоматическое привязывание к интерфейсу default route не включается: оно обходило бы host routes/policy routing. При изменении порядка секций сверять и nft priority sets, и sing-box rules; не предполагать приоритет по одному визуальному названию.

## DNS
Разделять bootstrap resolver, основной DNS, fake-IP и реальное назначение. Fake-IP из `198.18.0.0/15` или внутренних IPv6 диапазонов не является реальным адресом сервиса; запрос должен попасть в соответствующий перехват ядра. `nslookup` через локальный DNS и внешний resolver может закономерно возвращать разные адреса. Ошибка сертификата при fake-IP требует проверить путь перехвата/состояние ядра, не отключать TLS validation.

Настройка «DNS через секцию» влияет на resolver и может создавать зависимость доступности DNS от прокси. Подмена DNS не меняет IP/маршрут подключения к VPS, заданному явным IP. IPv4 и IPv6 проверять отдельно; отсутствие рабочего IPv6 не доказывает сбой IPv4.

`pre_routing_resolve_mode`: `disabled` по умолчанию, `all` либо `selected`. После служебных исключений и до пользовательских правил генератор добавляет `resolve` с явным основным `dns-server`, чтобы получить реальные адреса вместо Fake-IP. Порядок секций не меняется: верхнее правило по IP выигрывает только при совпадении; иначе может совпасть нижнее правило по домену. `pre_routing_resolve_domains` использует обычный домен для suffix и `full:` для точного совпадения; пустой выбранный список не принимается. Статичные hosts и служебные контрольные домены исключены из нового шага. Домен должен быть известен к этому моменту; серверный sniff, добавленный позже, не действует задним числом.

## WARP, VLESS, Zapret2 и Tailscale
WARP регистрирует/получает профиль через Cloudflare API: недоступность API и неинициализированный endpoint отличать от отказа VLESS. Каскад VLESS через WARP меняет путь до VPS и добавляет зависимость от WARP; это не доказательство конкретного механизма фильтрации прямого пути.

Zapret2 получает только трафик соответствующей секции/mark, не весь TCP/UDP роутера. Нельзя одновременно запускать стороннюю службу с собственной политикой NFQUEUE. Настройки секций должны исключать рекурсивный захват пакетов самого туннеля.

Системный Tailscale отдельно от встроенных возможностей ядра: exit node увеличивает проходящий трафик и нагрузку; доступ к LuCI не гарантирует доступ к Clash API, который может слушать только LAN-адрес. Не открывать API в WAN как универсальное решение. Изменение firewall/listen проверить с сохранением удалённого доступа и откатом.

Политика доступа серверов вне этого репозитория. Требования безопасности и ограничения тестов — [SECURITY](SECURITY.md).

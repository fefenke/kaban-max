# Безопасность разработки и публикации

Обязательные ограничения для всех задач. Не являются утверждением о фактических настройках живых серверов.

## Доступ и внешние действия

- Роутеры/VPS, установка, публикация, изменение firewall/серверов и нагрузочные проверки требуют отдельного запроса. Разрешение в старом отчёте не переиспользуется.
- Не отключать серверный RU blackhole самовольно. Не проводить тесты, раскрывающие реальный IP VPS российским сервисам. Наличие/содержимое живого blackhole нужно подтверждать отдельно.
- Не открывать Clash API/админку в WAN без явно согласованной необходимости, аутентификации и firewall-политики. Наличие Tailscale не делает bind безопасным или доступным автоматически.
- Read/exec permission не даёт write-RPC. Проверки session ACL, core API secret и source/scope обязательны также в тестируемых мутациях.

## Сетевое разрешение

Сохранять first-match, source/device/inbound scope, инфраструктурные и VPS/RU ограничения. Не считать голый TCP dial, чужой flow или reverse DNS разрешением на Direct. Не отключать TLS/certificate/protocol verification ради прохождения теста. Ручное направление и проверенная автоматическая альтернатива имеют разные контракты; детали — [NETWORKING](NETWORKING.md), [авторутинг](AUTO_ROUTING_STORAGE.md).

## Приватность и файлы

Для публичного выпуска: `scripts/audit-release-privacy.py` проверяет source и распакованные IPK payloads, включая сравнение с точными private reference values без их вывода. APK/IPK и каждый backend file сверяются через `inspect-release.py`. Разрешены только явно рассмотренные public test PKI/upstream attribution по точным fingerprints; неизвестный ключ или email требует проверки. `.local`/конфиги/журналы не включаются в assets. Текущие PNG metadata очищены без изменения пикселей. История сохраняется по явному выбору пользователя; новые commits используют только project identity.

- `.local/` может содержать реальные конфиги, ключи, логи, старые репозитории и временные результаты. Исключение из Git не гарантирует отсутствие секретов в старой истории. Не публиковать каталог целиком.
- Не выводить ключи/URI/полные реальные конфиги в tool output и отчёты. Synthetic fixtures не должны содержать реальные адреса инфраструктуры.
- Перед публикацией проверять staged diff, состав assets, manifests и текст документов. Отсутствие совпадений сканера не доказывает отсутствие секретов.
- Обнаружение секрета в истории требует отзыва и отдельно согласованной работы с историей. Удаление текущего файла не устраняет прежнюю утечку.
- Private autoroute metadata не передаётся в public page; компактный файл всё равно содержит адреса/связи устройств и должен оставаться приватным. Support exports должны маскировать чувствительные данные.
- Документационный архив содержит только снимки инженерных документов, не приватный `.local/`. Он исключён из сборки пользовательского сайта.

## Проверки и восстановление

Использовать loopback/synthetic TLS/DNS/IP и изолированные контейнеры. NET_ADMIN, если требуется тестом, только в отдельном namespace без host networking и без очистки чужих nft tables. Не путать локальный тест с аппаратной приёмкой.

Изменения сохраняют Git-историю и возможность отката. Не удалять пользовательский diff, данные и старые релизы ради «чистоты». Runtime-публикация/установка не являются частью обычного рефакторинга или обновления документации.

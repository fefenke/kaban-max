# Безопасность разработки и публикации

## Доработка ordinary HTTPS, 2026-11-16

Обычный HTTPS не равен strict nonce freshness: только ручное предложение после двух исходных transport failures и двух пригодных ответов альтернативы. Неверный TLS, HTTP access/rate-limit/anti-bot и отсутствие identity не дают Apply. IP-only diagnostic — только TCP, после атрибуции/guards, без application success. Нет DNS expansion или lease на mixed address set; RU blackhole/VPS policy не менялись. Новые tests также network-none, без реального внешнего трафика.


## Автомаршрутизация №04Б

RU blackhole и VPS-маршруты не менялись. Probe никогда не выбирает VPS; opt-in отказывается от неизвестных infrastructure endpoints/subscriptions и основного DNS через VPS/opaque health groups. Неизвестная identity/first-match/TLS/freshness означает отсутствие разрешения на Direct. Write-RPC требует session ACL, core POST — непустой API secret; generic read/exec не предоставляет запись. Контракты и suppression маскируются в support-экспорте. В тестах использованы только network-none контейнеры, synthetic TLS/DNS/IP и отдельная nft table внутри контейнера. [Границы](AUTO_ROUTING_IMPLEMENTATION_04B.md).


Публичные исходники отделены от `.local/`, куда перенесены приватные исследования, конфиги, SSH-материалы и старые checkout. `.gitignore` защищает от обычного add, но не от `git add -f`, публикации архива, вложенного Git или раскрытия через вывод команд. Docker build context также исключает `.local/`. Не включать этот каталог в сайт документации/релизные assets.

Перед публикацией проверять staged diff, имена/содержимое assets, URI, ключи/токены, адреса реальных серверов и логи. Если обнаружен реальный секрет в Git-истории, удаление текущего файла не устраняет утечку: отозвать секрет и отдельно согласовать очистку истории. История в ходе изоляции не переписывается. Локальный сканер лишь вспомогателен; публичная история не считается автоматически прошедшей полный secret audit.

## Ограничения сетевой диагностики
- Не отключать серверный RU blackhole самовольно. Его наличие/содержимое на действующих VPS в этой задаче не подтверждалось: это ограничение безопасности для будущих действий, а не факт текущего server config.
- Не проводить тесты, раскрывающие реальный IP VPS российским сервисам; использовать согласованные нейтральные контрольные адреса. Не подменять их произвольным поисковиком ради нагрузки.
- Реальные роутеры/VPS/удалённая инфраструктура — только с отдельным разрешением. Разрешение локальной уборки не разрешает SSH, изменение маршрутов или публикацию.
- Сетевые изменения обратимы; менять один параметр, фиксировать исходное состояние, подготовить откат с сохранением доступа.
- Не открывать Clash API/админку в WAN без отдельной необходимости, аутентификации и firewall-политики. Tailscale не делает любой bind автоматически доступным.

Содержимое пользовательского трафика для fallback evidence не сохраняется: учитывается первый положительный read нового TCP-соединения и идентичность outbound в текущем раунде. Наблюдения RAM ограничены 24h, подробные события ≤50. Это не заменяет оценку приватности прочих журналов и экспортируемых конфигураций.

Приватный архив намеренно сохранён для восстановления. В нём могут оставаться действующие SSH-ключи и конфиги; перенос не означает их отзыва. Удаление/ротация — отдельная согласованная задача. Не выводить их в терминал/ответы и не синхронизировать публично.

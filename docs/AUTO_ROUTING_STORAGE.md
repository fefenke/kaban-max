# Хранение и очистка авторутинга — локально r24

Локальный r43 сохраняет историю Applied ошибок, но показывает статус «Правило применено», без per-IP follow-up jobs. Явный TCP-risk opt-in имеет отдельный evidence, не обходит IP-only/scope/исключения и не притворяется protocol proof. [Контракт r43](AUTO_ROUTING_R43.md).

Локальный r42 добавляет selected-route Warn и bounded retry неуспешного web transport check после прежних5мин. Успешный Pending не перепроверяется; Failure/OriginalFailure, permissions, retention и flash schedule прежние. [Разбор Applied/Pending](AUTO_ROUTING_PENDING_RETRY.md), [тесты](WARP_RUNTIME_FIX.md).

Hotfix r41 сохраняет bounded failure_reason для applied_route_bypassed/applied_target_failed в RAM sidecar. Поздняя ошибка альтернативы заменяет прежнюю причину обхода; старые сведения без attribution не приписываются выбранному маршруту. Routing permissions, flash schedule и budget неизменны. [Late-DNS исправление](AUTO_ROUTING_LATE_DNS.md).

Приём ошибки в registry и её видимость в журнале — разные проверки: исходная транспортная ошибка публикуется на Warn. Executable harness включает этот уровень и отдельно проверяет disabled logging, запрет auto-apply для неизвестного протокола и положительное HTTPS body evidence. Retention сохранённых результатов от log level не зависит.

2026-11-23. Изменения поверх локального r23, исходный HEAD `98e5605`. Пользователь разрешил завершить обсуждённую схему без агентов. Первоначальные локальные проверки не включали установки/подключения. Позднее согласованный preview **0.2.3/r29** установлен на один ARM64 роутер: module defaults и сохранность durable JSON проверены, active sources остались выключенными. Свежие полные suites и точный scope — [PREVIEW_023](PREVIEW_023.md). Общий OOM при выключенном авторутинге — отдельная недиагностированная проблема; эта работа не объявляет его устранённым.

## Итоговая схема

**Текущий контракт r35 заменяет возрастное удаление Pending:** неразобранные ошибки и результат проверки сохраняются до удаления, применения или исключения записи под прежним byte budget. Успешная альтернатива не протухает и не запускает автоматический recheck; новые исходные ошибки показываются отдельно. Исторический результат не продлевает внутреннее разрешение автоматического grant. Private checkpoint сохраняет результат через restart; `checked_at` — время проверки, не истечение срока. Retention очищает прочую временную диагностику. Кнопки перепроверки нет. Сохранность нового Pending при полном power loss отдельно не заявляется. [Контракт, миграция, проверки](PREVIEW_026.md).

r34 был промежуточным исправлением: отделял deadline применения от retention диагностики, но продолжал показывать expired. Пользователь отверг протухание сохранённого результата; этот контракт заменён r35 выше. [Исторические RED/GREEN](PREVIEW_025.md).

| Настройка в основных настройках | По умолчанию | Допустимые значения |
| --- | --- | --- |
| Период сохранения авторутинга | `1d` | от `15m` до `30d`, включая `12h` |
| Бюджет памяти авторутинга | `4` МиБ | целое от 1 до 32 МиБ |

UCI: `auto_routing_save_interval`, `auto_routing_memory_mib`. Поле cleanup interval удалено в 0.2.7; legacy `auto_routing_cleanup_interval` игнорируется. Pending ограничены памятью и хранятся до разбора. Defaults не записываются при no-op Save; interval flash перечитывается backend, изменение memory budget требует обычного Save & Apply/reload.

1. Маршруты и исключения действуют из RAM. Flash содержит атомарные компактные файлы `/etc/kabanmax/auto-routing-applied.json` и `/etc/kabanmax/auto-routing-suppression.json`. Формат совместим с прежним `version: 1`: ownership, scope, source/device/inbound/port, target и необходимые поля восстановления сохранены. Большие тексты ошибок, результаты проб, счётчики и накопленные доменные подписи в durable-файл не попадают. Старый расширенный формат читается и проецируется в компактный.
2. Каждый минутный capture под общим lifecycle lock обновляет рабочую RAM-копию. Только изменённые routing intents сохраняются во flash по монотонному интервалу. Нет изменений — нет записи flash и нет повторной записи того же снимка. Исключения записываются перед разрешениями. Повреждённый существующий flash-файл не перезаписывается молча.
3. Досрочный checkpoint возможен при давлении core-памяти или если изменённые относительно flash записи занимают 75% бюджета компактного хранилища. Считаются именно dirty-данные, включая удаления; полный, но неизменный реестр не вызывает запись. Общий нижний предел между checkpoint — 15 минут. Досрочное сохранение не заменяет очистку и само не освобождает активные маршруты из RAM.
4. Лимиты 64 маршрута/ошибки/исключения убраны из core, backend, восстановления и интерфейса. Используется консервативный учёт байтов: половина core-бюджета — основные данные и индексы, половина — временные данные, включая контекст ещё не завершившихся соединений. Backend допускает компактные applied+excluded данные до четверти настроенного бюджета, оставляя запас под JSON/копии. Это не жёсткий лимит RSS процесса sing-box и не измерение всей памяти роутера.
5. Периодический sweep очищает cooldown, историю и диагностические остатки без неразобранной записи. Необработанные ошибки и связанные результаты по возрасту не удаляются. При давлении освобождаются подробности действующих grants; свежая ошибка альтернативы не скрывается из-за старой даты создания маршрута. Разреженные maps пересоздаются, обычный Go GC освобождает payload/таблицы. Принудительного периодического GC, drop_caches, очистки системного `/tmp` и restart ради уборки нет.
6. Действующие persistent grants и исключения не удаляются ради новых. Снижение бюджета не выбрасывает уже сохранённые маршруты. Рост, который не помещается после очистки, отвергается с явной причиной, существующая секция не выключается. Замена того же маршрута без роста допускается. Проверки остаются конечными и последовательными.
7. При внезапном отключении питания последние несохранённые изменения могут потеряться — пользователь это принял. Pending diagnostics остаются RAM-only. Обязательного flash-сохранения при каждом перезапуске нет: оно нарушило бы выбранную частоту записи.

## Интерфейс и границы мутаций

Public 0.2.3/r40 отделяет bounded RAM Applied diagnostics от compact routing intent: original/target errors, время/порт и наблюдённые имена сохраняются через restart службы; privacy/ownership/budget и flash interval неизменны. Пустая ошибка не рисуется. [Контракт и доказательства](RELEASE_023.md).

Обновление r39 от 2026-11-24 по явному запросу: persistent web approvals охватывают IP на всех устройствах/портах выбранной секции, origin scope остаётся metadata/ownership. Compact JSON сохраняет `all_devices`, старые approvals мигрируют без повторного probe. Dirty-only flash schedule прежний. [Точный контракт и проверки](AUTO_ROUTING_SECTION_IP.md).

Страницы остаются по 25/50/100 записей. Ответ страницы содержит selection только её строк; private `members` не пересылаются браузеру, чтобы один IP со многими устройствами не раздувал RPC. «Все» сначала собирает ID страниц выбранной секции/фильтра, затем подтверждает и выполняет batches по 8. Backend проверяет выбранные ID по всему тому же source/filter, а не только первой сотне. Между чтением и действием данные могут измениться: stale/foreign записи пропускаются, scope/ownership не расширяются. Направления отдельных строк сохраняются, для невидимых строк действует тот же выбранный по умолчанию выход.

Runtime disabled, ошибки capture и достижение бюджета показываются в реестре. Бюджет не добавляет физическую RAM и не разрешает бесконечное хранение: при заполнении одними основными данными новые добавления отклоняются без потери существующих. Для использования новых source-полей нужен core **1.14.4-r24**, в том числе при сохранённых маршрутах с выключенным сбором. Без автоматики и её сохранённых данных общий minimum остаётся r10.

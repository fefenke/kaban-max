## Согласованный контракт

Проверка обычного маршрута сохраняет5s. Выбранный fallback сообщает **TCP dial budget**, отдельно от health timeout: stable mode — одна попытка, обычный fallback — сумма доступных попыток. Авторутинг проходит выбранную цепочку групп с лимитом глубины8 и даёт этот бюджет плюс5s на TLS/HTTP. Для stable attempt_timeout8s получается13s; это максимум ожидания, не обязательная задержка. Общий deadline задания60s и отмена поколения не увеличиваются. HTTP transport может отделять dial context от request deadline; TCP probe теперь явно использует context задания, поэтому подключение также ограничено им.

Ниже «Разрешать перенаправление IP без домена» добавлена выключенная по умолчанию галочка **«Разрешать автоприменение без подтверждения протокола (риск)»** (`auto_routing_unconfirmed_protocol`). Она действует только при включённом автоприменении. Core option `allow_unconfirmed_protocol` не генерируется при выключенной опции, сохраняя совместимость старых конфигураций. Активная опция требует core r43; backend сообщает понятную ошибку на старом ядре до запуска.

Опция допускает альтернативу после двух успешных TCP-подключений к тому же наблюдённому IP/порту при неизвестном исходном протоколе. Нет отправки/повтора пользовательского payload. Эти попытки имеют Method=TCP, Status=transport_reachable, TLSVerified=false и Evidence=`unverified_protocol_tcp_reachable`: это **не доказательство работы сервиса или DPI**, интерфейс явно пишет «TCP доступен; протокол не проверен» / «Правило применено без подтверждения протокола».

Сохраняются source failure/admission, ownership, исключения, protected addresses, scope, generation, cooldown/hourly budget и две независимые попытки. Разрешение IP без домена остаётся отдельным. UDP-only проверка не получает такой обход; само созданное IP-правило по-прежнему охватывает все устройства/порты секции, как остальные persistent approvals. Известный TLS продолжает проверять сертификат; строгие nonce contracts не ослабляются. Соединение proxy/fast-open с отложенным handshake не считается установленным TCP. Выключение опции запрещает применение ещё не применённого слабого решения.

После Save & Apply уже сохранённый inconclusive/protocol_unconfirmed TCP record получает новую попытку, если активны новая опция и AutoApply. Данные старого результата не удаляются. Successful proposed result по-прежнему восстанавливается без перепроверки; UDP и выключенное согласие не включают этот обход.

**Уточнение пользователя о разовых сбоях:** у Applied показывается «Правило применено», без постоянного текущего предупреждения по одному timeout и без заявления «Новых ошибок нет». Исходная и последующие ошибки с датами сохраняются в раскрываемых деталях и Warn/Error журналах; поля/данные не удаляются. Периодические и новые проверочные задания для успешно применённых persistent IP не добавлялись. Реально наблюдённый обход применённого правила остаётся отдельным сообщением, а global WARP/fallback health checks сохраняются для переключения туннелей. Failed Pending retry из r42 сохраняется, successful Pending не перепроверяется.

Аудит сообщения `fallback active outbound failure [connection]`: общий `recordDialFailure` вызывается и при dial, и при позднем Read/Write/ReadBuffer/WriteBuffer. Фильтр исключает EOF, net.ErrClosed, context.Canceled, отменённый parent/fallback context, EAGAIN/EWOULDBLOCK. Остальные ошибки, включая ECONNRESET/EPIPE и deadline, могут будить health check исправного туннеля. Один stream уведомляет один раз; общий debounce5s и queue capacity1 сохранены. Ошибка сама не меняет выбранный туннель. `stableProbeError` сводит неизвестные причины к `request_failed`, поэтому точную причину пользовательской строки02:30:44 восстановить по ней нельзя. Термин `[connection]` не различает dial и stream. Поведение/уровни логов по результату аудита пока не менялись.

# Исправление автомаршрутизации после 0.1.8

Пользователь уточнил обязательный контракт: адрес подходит под условия исходной секции, именно она выиграла маршрутизацию, и имеется реальная ошибка этого соединения в журнале. Наблюдение без скачанных данных не является ошибкой. Чужой WARP-трафик и неатрибутированные наблюдения запрещено подмешивать в Zapret-секцию.

## Требования

- Общие формы: исходная более узкая колонка, подписи вместе с вопросиком выровнены вправо; Direct/WARP с пояснениями, затем auto-apply, IP-only под ним. Настройки не должны блокироваться после первого переключения.
- Только подтверждённая ошибка исходного соединения допускает запись/проверку. Ошибка сохраняет идентификатор для поиска в журнале и исходный source ID. Новый verifier не меняет принадлежность первой выигравшей секции.
- Автоприменение требует отдельной галочки, двух неудач исходного маршрута и двух проверенных HTTPS-ответов альтернативы. Для IP-only — явное разрешение и проверка сертификата непосредственно для IP; TCP connect не является успехом приложения. Scope source/device/inbound/port/IP/domain и TTL сохраняются.
- В списке доступны операции над своими ошибками: проверка, применение проверенного предложения, исключение и удаление. Удаление наблюдения не создаёт постоянного исключения.
- Обновление одинакового снимка не пересоздаёт DOM и не показывает Loading. Страницы — обычные номера с выделением текущей, без дробей/диапазонов; одна страница скрыта.

## Выполнение

1. RED-регрессии: чужой WARP/unattributed без ошибок не виден в META; повторные клики галочек; стабильный DOM/раскрытые детали; страницы 1/2/3; удаление pending.
2. Общий адаптер/контролы/реестр и backend selection/actions.
3. Новый patch поверх неизменённых 0001–0008: корреляция реальной ошибки с журналом, отказ от no-progress, scoped ordinary auto-apply и IP-only HTTPS, dismiss API. Новые core-тесты и clean apply/race/executable проверки.
4. Сверка source-only/logged failure/policy/TTL/DNS/CDN invariants на исполняемом ядре, frontend/backend/browser матрица, скриншоты. Обновление только затронутых документов с точными результатами и ограничениями.

Живые роутеры/VPS и сетевые нагрузки не разрешены. Проверки используют только изолированные synthetic fixtures. Предыдущее разрешение «публикуй когда будет готово» действует для полностью проверенного исправления; частичную реализацию не выдавать за готовую автоматику.

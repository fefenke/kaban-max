**Goal:** add explicit `chrome_155` while preserving `chrome`/empty/default as Chrome133, as selected by the user.

**Architecture:** retain pinned sing-box upstream plus existing stable-fallback patch. Add a second patch that pins the reviewed uTLS-lx dependency and exposes the explicit ID in TLS selection, schema and subscription/link parser. Do not replace the whole sing-box core with LX. Existing custom Firefox/Safari, REALITY keyshare options and record fragmentation retain their semantics.

## Limits

No live router/VPS, no publication. Chrome155 advertises MLDSA signatures that the pinned Go1.26/uTLS handshake cannot verify if a server selects them; Chrome trust-anchor hints do not replace OS RootCAs. This is faithful ClientHello behavior, not proof of full browser TLS identity or live availability. Classical keyshare/fragmentation deliberately alter the wire profile; tests must distinguish those options from default155. The reference fork itself does not claim a Chrome155 REALITY field test.
